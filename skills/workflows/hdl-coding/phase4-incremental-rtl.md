# Phase 4: 逐模块 RTL + MATLAB 验证 [MUST 硬约束]

> 所属工作流: `workflows/hdl-coding-workflow.md`
> 目标: 每模块写 RTL → 仿真 → 对比 MATLAB golden → 通过 → 下一模块。不可批量执行。

---

## [MUST] 逐模块验证流程

**这是工作流中最关键的硬约束。一旦违反，全链仿真时 bug 会堆叠无法定位。**

### 核心规则

```
按模块列表顺序，一次只处理一个模块。
完成当前模块的全部 RTL 编码 + 仿真验证 + MATLAB 对比后，才能开始下一个模块。
```

### 每个模块的完成标准（缺一不可）

| # | 标准 | 验证方式 |
|:-:|:-----|:---------|
| a | RTL 编码完成 | 遵循编码规范（ri_/ro_/i_rst 同步复位，三段式状态机） |
| b | `make compile` 通过 | 使用检测到的 EDA 工具链，无 lint 错误 |
| c | 仿真通过 | TB 自检逻辑全部 PASS |
| d | MATLAB golden 逐周期一致 | 关键中间信号逐一对比，输出逐周期匹配，误差 ≤ 1LSB |
| e | 差异修复 | 不一致 → 分析根因 → 修复 RTL → 重新仿真 → 再对比 |
| f | 记录验证矩阵 | 一致 → 输出一行到验证矩阵 → 开始下一模块 |

### 验证矩阵格式

每模块完成后输出一行：

```
| 模块名 | 状态 | 对比结果 | 迭代次数 |
|--------|------|----------|----------|
| scrambler | ✅ | 与 scrambler.m 逐周期一致 | 2/2 |
| equalizer | ❌ | H_est 累加器差 1LSB | - |
```

- ✅ = 与 MATLAB golden 逐周期一致
- ❌ = 未通过，需修复
- 迭代次数 = "通过时迭代次数/总迭代次数"

### 禁止跳过

- **禁止跳过任何模块的 MATLAB 对比验证**
- 如果 TB/测试向量未就绪，必须先完成 TB/向量再继续
- 如果某模块只有组合逻辑（无时序），仍需对比输出值

## 3-迭代复盘机制

当某模块修复超过 **3 次迭代**仍 FAIL：

```
问题迭代 ≥ 3次
  → 暂停调试
    → 5 Whys 解构根因
      → 定位流程漏洞（哪个 Phase 漏了检查）
        → 更新对应的工作流文件
          → 登记教训到 memory/learnings/
            → 确认根因解决后继续
```

不跳过、不妥协。重复出错说明流程有问题，不是记性差。

## 对称对模块高效编码

当处理到某个模块，且 `architecture.yaml` 中标注了它的配对模块
（`symmetric_with`）时：

1. **读取配对模块已完成代码** — 分析端口、参数、内部数据通路
2. **按对称类型推导**:
   - `dataflow_inverse`: 数据流反向，算法不变 → 端口镜像，控制逻辑取反
   - `identical`: 完全相同的模块（如 rrc_tx/rrc_rx）→ 相同端口不同实例
   - `structural_inverse`: 结构反向（如 fft/ifft）→ 内部模块反向连接
3. **生成框架** — 复用配对模块的端口列表、参数化定义、AXI4-Stream 接口
4. **差异点** — 只改写控制逻辑方向，数据通路保持一致性

此机制**不跳过 MATLAB 验证**——框架生成后仍须编译→仿真→golden 对比。

## Bit-True 验证报告

每模块完成后输出 Bit-True 验证报告，包含：

- **定点 vs MATLAB 浮点误差** — NMSE / EVM / 最大误差
- **资源使用** — LUT / FF / DSP / BRAM（实际 vs 预算）
- **时序收敛** — Fmax（WNS / TNS）
- **接口时序** — AXI4-Stream 握手时序图
