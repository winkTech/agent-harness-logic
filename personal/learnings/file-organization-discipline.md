# 文件管理纪律

## 规则

工作过程中所有文件必须有条理地分类存放：

1. **仿真输出** → 归入 `sim/` 或 `sim/<test_name>/` 目录，不得放在项目根目录
2. **测试文件**（Testbench、测试向量）→ 归入 `tb/` 或 `tests/` 目录
3. **文档**（设计文档、报告）→ 归入 `docs/` 目录，按 `docs/plans/`、`docs/reports/` 等子类细分
4. **脚本/工具** → 归入 `scripts/` 目录
5. **生成文件**（编译产物、波形、日志）→ 归入 `build/`、`logs/` 或 `.out/` 目录，应在 `.gitignore` 中排除

## 为什么

- 项目根目录散放文件导致难以导航
- 仿真输出混在源码中容易误提交
- 分类清晰的目录结构让新人（和未来的自己）能快速定位

## 如何应用

- 创建文件时先确认目标目录是否存在，不存在则先建目录
- 拒绝"先放根目录，之后再整理"的惰性思维
- 写 RTL 时：`src/<module>/`；写 TB 时：`tb/<module>/`；跑仿真时：输出定向到 `sim/<test_name>/`
- 引用文件时使用相对路径，保持目录结构可移植

**Why:** 用户明确要求文件管理必须有条理，仿真输出与测试文件不能乱放。

**How to apply:** 每次创建或移动文件时，主动检查目标归类是否正确。不贪方便放根目录。
