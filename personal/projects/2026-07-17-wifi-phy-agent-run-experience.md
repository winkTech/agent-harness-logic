# WiFi PHY 项目执行经验

## 经验边界

本总结来自 1326 条无信息量的工具成功记录和 329 条自动失败模板。失败记录主要反映 Agent 工作树、路径、Shell、门禁和仿真环境问题，不能作为 PHY 功能完成度、RTL 正确性或正式验收结果的证据。

正式项目状态仍须以提交锚点、机器可读结果文件和新鲜的端到端验证为准；不得用日志数量或单模块成功次数代替整机闭环。

## 可复用项目经验

### 1. Agent 启动前先固定工作树

1. 解析并打印仓库根目录和目标 worktree 的绝对路径。
2. 验证目录存在、位于预期项目根下，并确认 Git 状态可读取。
3. 验证本轮需要的规格、源文件、测试向量和门禁文件存在。
4. 任一检查失败即停止该 worker，不在同一失效路径上重复重试。

工作树名称和真实路径必须由父 Agent 统一分配；子 Agent 不自行猜测 `retry1`、`codex_wifi_phy` 等目录。

### 2. 文件操作必须区分文件和目录

读取、复制或解析前先检查目标存在性和类型。`EISDIR` 不是业务失败，而是调用契约错误；同一路径第二次出现时应修正路径解析逻辑，而不是继续记录新错误文件。

### 3. 跨 Shell 操作保持单一边界

- Windows 路径、PowerShell、Git Bash 和 EDA 命令不要在一条长内联命令中混用。
- 复杂 Python、仿真或批处理逻辑使用已有脚本文件，不拼接多层引号。
- 文件移动、清理和路径枚举使用同一个 Shell 完成。
- 命令失败后保留原始退出码与第一条有效错误，不把整段重复输出当成新经验。

### 4. 门禁失败与功能失败分开处理

退出码 49 表示需求或验证门禁未满足，应检查 `var/gates/requirements-gate.json`、`var/gates/verification-quality.json` 以及对应规格/向量清单。它不能被解释为 RTL 功能失败，也不应触发无界重试。

门禁通过只代表前置条件齐备；功能验证仍须由仿真、Golden Model 对比或端到端结果证明。

### 5. 仿真采用有界、单目的运行

运行前检查：

- EDA 可执行文件和许可证可用；
- 顶层、文件清单、Make 目标和测试向量存在；
- 上一次仿真进程已退出，VCD/WLF 等产物未被占用；
- 输出目录可写且不会覆盖正式验收证据。

长时间或多目标命令失败后，切换为一个目标、一个 case、一个机器可读结果的有界运行。语法检查不能替代功能验证。

### 6. 大产物只提取必要证据

大日志、波形和报告使用 offset/limit、关键词定位或专用解析器分段读取。长期记忆只保存根因、修复、验证证据和预防规则，不保存整份日志。

### 7. 多 Agent 结果必须进入统一账本

父 Agent 记录每个 worker 的工作树、任务边界、开始/结束时间、结果文件和阻塞原因。重复失败按错误指纹聚合为一条，并记录次数与首末时间；子 Agent 的单次工具成功不形成项目记忆。

## 记忆保留规则

- 不记录逐工具成功事件。
- 未分析的错误模板只属于短期遥测，不属于长期记忆。
- 只有包含“根因、修复、验证、预防”的结论进入项目经验。
- 同类错误在一个 session 内聚合，不按发生次数创建文件。
- 项目经验保留一份当前有效版本；被替代内容显式标记 `superseded_by`。
