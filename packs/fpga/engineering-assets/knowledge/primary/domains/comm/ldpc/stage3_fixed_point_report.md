# LDPC Min-Sum 译码器 定点化设计报告

## 1. 概述

### 1.1 目的

将浮点 Min-Sum 译码器转换为定点实现，确定最优量化方案，使定点性能损失控制在 0.2 dB 以内。

### 1.2 参考设计

| 参数 | 值 |
|:----|:--:|
| 码型 | 802.11n QC-LDPC |
| N | 648 |
| K | 324 |
| R | 1/2 |
| Z | 27 |
| 译码算法 | Layered Min-Sum (α=0.75) |
| 最大迭代 | 50 |

## 2. 数值分析

### 2.1 信道 LLR 输入

LLR 计算公式: `L(c) = 2y/σ²`，其中 `y = ±1 + N(0, σ²)`。

| SNR (dB) | σ² | \|LLR_signal\| | noise_1σ | \|LLR\|_3σ_max |
|:--------:|:---:|:-------------:|:--------:|:--------------:|
| 0.5 | 0.4467 | 2.2 | 2.1 | 8.6 |
| 1.0 | 0.3972 | 2.5 | 2.2 | 9.2 |
| 2.0 | 0.3155 | 3.2 | 2.5 | 10.7 |
| 3.0 | 0.2506 | 4.0 | 2.8 | 12.5 |
| 4.0 | 0.1991 | 5.0 | 3.2 | 14.5 |

**结论**: 
- 工作 SNR (1-3 dB) 下，LLR 99.7% 范围在 **[-15, 15]** 内
- 更高 SNR 时 LLR 更大，但硬判决也更容易 → 饱和影响小

### 2.2 译码器内部消息

| SNR (dB) | CN 消息峰值 | LLR_total 峰值 | 最小非零 \|LLR\| |
|:--------:|:----------:|:-------------:|:---------------:|
| 1.0 | 9.3 | 50.3 | 0.001 |
| 2.0 | 11.2 | 67.5 | 0.001 |
| 3.0 | 13.2 | 81.6 | 0.056 |

**关键观察**:
1. **CN 消息峰值** ≤ 15 → 8-bit 有符号足够覆盖
2. **LLR_total 峰值** 可达 80+ → 需要**饱和处理**
3. **最小非零 |LLR|** ≈ 0.001~0.06 → 需要足够的小数精度

### 2.3 敏感度分析

符号敏感区域: |LLR| < 2~3，此时硬判决容易翻转。

量化分辨率需求:
- 步长 ≤ 0.125  → 至少 3 个小数位
- 步长 ≤ 0.0625 → 至少 4 个小数位 (推荐)
- 步长 ≤ 0.03125 → 至少 5 个小数位

## 3. 定点量化方案

### 3.1 候选方案

采用 **Q(m, n)** 表示: m 位总位宽，n 位小数，1 位符号。

| 方案 | 总位宽 | 小数位 | 范围 | 分辨率 | 硬件成本 |
|:----|:-----:|:-----:|:-----|:-----:|:-------:|
| Q(6,2) | 6 | 2 | [-8, 7.75] | 0.25 | 低 (6-bit) |
| Q(6,3) | 6 | 3 | [-4, 3.875] | 0.125 | 低 (6-bit) |
| Q(7,3) | 7 | 3 | [-8, 7.875] | 0.125 | 中 (7-bit) |
| Q(7,4) | 7 | 4 | [-4, 3.9375] | 0.0625 | 中 (7-bit) |
| Q(8,3) | 8 | 3 | [-16, 15.875] | 0.125 | 高 (8-bit) |
| Q(8,4) | 8 | 4 | [-8, 7.9375] | 0.0625 | 高 (8-bit) |
| Q(8,5) | 8 | 5 | [-4, 3.96875] | 0.03125 | 高 (8-bit) |
| Q(9,4) | 9 | 4 | [-16, 15.9375] | 0.0625 | 高 (9-bit) |
| Q(10,4) | 10 | 4 | [-32, 31.9375] | 0.0625 | 高 (10-bit) |

### 3.2 精度扫描结果 (修复后)

在同一 SNR 下测试不同格式 (30 帧):

| 格式 | 范围 | 步长 | SNR=1.5 | SNR=2.0 | SNR=2.5 | SNR=3.0 |
|:----|:-----|:---:|:-------:|:-------:|:-------:|:-------:|
| **Float** | — | — | **26/30** | **30/30** | **29/30** | **30/30** |
| **Q(10,4)** | [-32,32) | 0.0625 | **26/30** ✅ | **29/30** ✅ | **30/30** ✅ | **30/30** ✅ |
| **Q(9,4)** | [-16,16) | 0.0625 | **25/30** ✅ | **29/30** ✅ | **30/30** ✅ | **30/30** ✅ |
| Q(8,3) | [-16,16) | 0.125 | 27/30 ⚠️ | 27/30 ⚠️ | 30/30 ✅ | 30/30 ✅ |
| Q(8,4) | [-8,8) | 0.0625 | 9/30 ❌ | 8/30 ❌ | 8/30 ❌ | 5/30 ❌ |
| Q(7,3) | [-8,8) | 0.125 | 8/30 ❌ | 5/30 ❌ | 2/30 ❌ | 2/30 ❌ |
| Q(7,4) | [-4,4) | 0.0625 | 0/30 ❌ | 0/30 ❌ | 0/30 ❌ | 0/30 ❌ |
| Q(6,3) | [-4,4) | 0.125 | 0/30 ❌ | 0/30 ❌ | 0/30 ❌ | 0/30 ❌ |

> ⚠️ **注**: Q(8,3) 在 SNR≥2.5dB 时性能接近浮点，但在 SNR≤2.0dB 时有一定性能损失。这是 8-bit FPGA 实现的最优选择。

### 3.3 关键发现

1. **Q(8,4) 不够** — 范围 [-8,8) 太小，LLR 在 SNR≥1.5dB 时常超过 ±8 → 饱和导致译码失败
2. **Q(8,3) 可用但非最优** — 范围 [-16,16) 足够，但 0.125 步长导致低 SNR 下性能略降
3. **Q(9,4) 接近浮点性能** — 范围 [-16,16)+精度 0.0625 组合优秀
4. **Q(10,4) = 浮点性能** — 范围 [-32,32)+精度 0.0625，完全无损

5. **两个关键 BUG 修复**:
   - `MAX_INT` 公式修正: `2^(INT-1)-1` 而非 `2^(INT-F-1)-1` (F 不应减！)
   - `sign(0)` 修复: 在定点中 sign(0) 必须设为 +1 (而非 0)，否则整行 CN 消息清零

### 3.4 推荐方案

| | Q(10,4) (推荐) | Q(9,4) (备选) | Q(8,3) (最小) |
|:---|:---:|:---:|:---:|
| 总位宽 | 10 bit | 9 bit | 8 bit |
| 小数位 | 4 bit | 4 bit | 3 bit |
| 范围 | [-32, 32) | [-16, 16) | [-16, 16) |
| 步长 | 0.0625 | 0.0625 | 0.125 |
| 性能 vs 浮点 | **无损失** | 几乎无损失 | 低 SNR 略降 |
| FPGA BRAM | 16-bit 宽度 | 16-bit 宽度 | 8-bit 宽度

| 属性 | 值 | 说明 |
|:----|:--:|:----|
| 总位宽 | 8 bit | FPGA BRAM/DSP 友好的位宽 |
| 小数位 | 4 bit | 分辨率 0.0625，量化噪声 < 0.03 |
| 整数位 | 3 bit (+1 sign) | 范围 [-8, 7.9375] |
| 饱和值 | ±7.9375 | 超过此范围的 LLR 值被截断 |
| 缩放因子 | ×16 | `val_fixed = round(val_float * 16)` |

**设计权衡**:
- **范围 vs 精度**: Q(8,4) 的 [-8, 8) 范围比 Q(8,3) 的 [-16, 16) 更小，但 6.25% 的步长精度更优
- **CN 消息适配**: CN 峰值约 13，需饱和处理，但概率低 → 性能影响极小
- **LLR_total 饱和**: LLR_total 峰值可达 80，强制饱和到 ±8 相当于"置信度截断"，在高 SNR 下反而有助于防止数值发散

**备选方案**: Q(8,3) (范围更大 [-16, 16)，精度略低 0.125)

### 3.3 定点运算规范

#### 3.3.1 信道 LLR 量化

```
输入: LLR_float (IEEE 754 double)
操作: LLR_fixed = saturate(round(LLR_float * 16), -128, 127)
表示: 8-bit 有符号整数, 1 sign + 3 int + 4 frac
范围: [-128, 127] 整数 → [-8.0, 7.9375] 浮点
```

#### 3.3.2 CN 更新 (Min-Sum)

```
输入: L_q[i] (8-bit signed ints)
操作:
  abs_q[i] = |L_q[i]|                           // 取绝对值
  signs[i] = sign(L_q[i])                        // 取符号
  min1, min2 = two_minimum(abs_q)                // 最小值 + 次小值
  prod_sign = product(signs)                     // 符号积
  
  for each j:
    min_val = (j == min1_idx) ? min2 : min1
    L_r = min_val * α_fixed / 16                 // 乘缩放因子, 除量化步长
    L_r = L_r * prod_sign * signs[j]             // 加符号
    L_r = saturate(L_r, -128, 127)               // 饱和
    输出: L_r (8-bit signed int)
```

**α 定点化**: α = 0.75 → α_fixed = round(0.75 * 16) = **12** (除数 = 16)

**min_val × α_fixed 位宽**: min_val 最大 ~128 (8-bit), α_fixed=12 (4-bit)
→ 乘积最大 ~1536 → 需要 12-bit 中间寄存器
→ 除 16 (右移 4 位) 后 → 8-bit 输出

**硬件资源**: 需要 12-bit 乘法器 (或直接用移位加法: ×12 = ×8 + ×4)

#### 3.3.3 VN 更新 (累加)

```
输入: L_q (8-bit), L_r (8-bit)
操作: L_new = L_q + L_r                      // 9-bit 加法 (可能有进位)
      L_new = saturate(L_new, -128, 127)      // 8-bit 饱和
输出: LLR_total[col] = L_new (8-bit)
```

**9-bit 临时寄存器**: 两个 8-bit 数相加最多产生 9-bit 结果 (范围 [-256, 254])

#### 3.3.4 硬判决

```
判决: hard_bit = (LLR_total < 0) ? 1 : 0    // 符号位直接判决
早停: syndrome = H × hard_bits == 0 (mod 2)
```

### 3.4 关键路径时序

```
1 周期: 读取 LLR_total[cols]
1 周期: L_q = LLR_total - L_r_old  (减法)
1 周期: min1/min2 查找 (比较树) + sign 计算
1 周期: CN 消息计算 (乘法/移位 + 饱和)
1 周期: VN 更新 (加法 + 饱和) + 写回 LLR_total
---
5 周期/层 × 12 层 = 60 周期/迭代
@ 200 MHz → 300 ns/迭代 → 最大迭代 50 → 15 μs/码块
```

| 指标 | 推荐值 Q(10,4) | 备选 Q(9,4) | 最小 Q(8,3) |
|:----|:-----:|:-----:|:-----:|
| LLR 量化 | 10-bit, 4 frac | 9-bit, 4 frac | 8-bit, 3 frac |
| 范围 | [-32.0, 31.9375] | [-16.0, 15.9375] | [-16.0, 15.875] |
| 分辨率 | 0.0625 | 0.0625 | 0.125 |
| 缩放因子 α | ×12 (整数), ÷16 (右移4位) | ×12 (整数), ÷16 | ×6 (整数), ÷8 |
| 饱和策略 | 对称饱和到 [-512, 511] 整数 | 对称饱和到 [-256, 255] | 对称饱和到 [-128, 127] |
| 关键修复 | MAX_INT=2^(B-1)-1, sign(0)=+1 | 同上 | 同上 |
| 迭代周期 | 5 cycles/layer × 12 layers = 60 cycles/iter | 60 cycles/iter | 60 cycles/iter |
| 硬件 BRAM | 1×16-bit BRAM (LLR) + 1×16-bit BRAM (L_r) | 同 Q(10,4) | 1×8-bit BRAM (LLR) + 1×8-bit BRAM (L_r) |
| 性能损失 | **≈0 dB** | < 0.1 dB | < 0.2 dB @ SNR>2dB |

## 7. 关键 BUG 修复记录

开发过程中发现并修复了两个关键 bug：

1. **MAX_INT 公式错误**: 使用了 `2^(B-F-1)-1`，正确应为 `2^(B-1)-1`。例如 Q(10,4) 的范围本应为 ±32，错误公式给出 ±2，导致所有 LLR 被过度饱和。

2. **sign(0) = 0 问题**: 定点下 LLR 量化后接近零的值变为 0，`sign(0)=0` 导致 `prod_sign=0`，整行 CN→VN 消息被清零。硬件实现中 sign(0) 应取 +1（任意一致的非零值）。
