## [1.1.0] — 2026-08-04 帧尾自动冲刷：补上每帧丢一个数据符号的功能洞

**行为契约变更**，故走次版本号并**重新签字**。需求门禁记录见
`var/gates/requirements-gate.json`（六维全 `confirmed`，事实全部来自实测）。

### 问题

M1 实链上每帧稳定丢**最后一个数据符号**。帧结束后本模块转 UNSYNC 静默，
下游 `fft64_sdf` 的各级 FIFO 只在有效拍移位，它流水里最后一个真符号就永远出不来。
xsim 实链实测：`TAIL_STUCK 64` 样点。

`fft64_sdf` 的 limitations §5 早写了"拉低 `i_valid` 不排空流水"，但整条链路里
**没有任何人负责补这个冲刷**——这正是"靠上游行为碰巧成立"的隐性契约会出的事。

### 实现

数满 `i_cfg_n_sym` 后进新增的 `S_FLUSH` 段，自驱吐 **64 拍** `o_valid` 高、数据恒零
的样点，再回 UNSYNC。输出长度由 `(2+n_sym)×64` 变为 `(2+n_sym)×64 + 64`。

三个设计点，都是实现过程中被实测逼出来的：

1. **自驱**（不等 `s_axis_tvalid`）。初版靠输入拍推进，结果 cosim 里激励在帧尾正好
   用完、冲刷根本没发生——"最后一个符号能不能出来"竟取决于上游帧后是否续流。
   自驱后该依赖消失。
2. **冲刷段响应 `i_fft_start`**。初版不响应，实测中它吞掉了第二帧的起窗脉冲、
   整帧丢失——等于把帧间最小间隔从 1 拍抬到 65 拍。新帧的样点本来就会把上一帧的
   尾巴挤出去，冲刷此时已无必要，故直接中止。
3. **恒零而非透传帧后噪声**。零是确定值，cosim 能 0 容差判定；透传会把判据和帧后
   激励无谓地耦合。

**不会给下游造出假符号**：这 64 拍把最后一个真符号挤出去的同时，自己成为 fft64
流水里新的"卡住的那一个"。这一条要紧——`channel_est_top` 的相位 FSM 是
`P_DATA → P_DATA` 自环、没有帧长概念，任何多出的符号都会产出多余的 H。

### 验证

- 链路级（xsim，`cp_remove → fft64_sdf → channel_est_top`）：切窗样点 1280，
  实际吐出 fft64 **1280**（修复前 1216）——**永久卡死的切窗样点由 64 变 0**。
- `tb_cp_remove_cosim`：对治理 golden **2176 点 0 失配**，另加冲刷段 64 拍全零的
  独立断言。
- `tb_cp_remove_stability` 新增两条锁定断言：零间隔仍整帧丢失（未变）、
  **冲刷进行中（间隔 4 拍）起新帧必须完整跑出**。

### golden 未改

初稿门禁写了"golden 须同步建模冲刷"，实现时判定那是错的：`rx_cp_window` 的职责是
802.11a **切窗序列**参考，冲刷是为 fft64 流水不自排空所做的迁就，不属切窗语义。
把下游实现细节塞进协议参考模型是污染而非同步。改为 golden 仍 0 容差判 2176 点，
TB 侧显式断言冲刷段——覆盖率不降，且不必触碰受保护模型。

## [1.0.1] — 2026-08-04 实链测量修正 + 第二仿真器交叉验证

**推翻了自己写下的一条"硬依赖"。** 1.0.0 的 limitations §2 与 signoff 都写着
"`fft64_sdf` 与 `channel_est_top` 之间必须有弹性缓冲，是 M1 硬依赖"。那是读
`channel_est_top` 的节流条件**推**出来的，不是测出来的。

2026-08-04 在 xsim 上搭真实链路（`cp_remove → fft64_sdf → channel_est_top`，
两帧背靠背，中间放理想无限深 FIFO 观测占用）实测：

| 场景 | 反压总拍 | 最长连续 | 缓冲峰值占用 |
|---|---|---|---|
| 真实 M1 链路 | **0** | 0 | **1** |
| 对抗：去掉 CP 间隙 | 22 | 4 | 23 |

**本模块每符号只占 64 拍、留出的那 16 拍 CP 空档，就是下游需要的全部弹性**——
连第二帧起始那条 `w_stall_frame` 路径也从未触发。M1 配置下不需要弹性缓冲。
结论依赖 CP 间隙存在；上游节奏若变，实测上界是 23 个条目。

**第二仿真器交叉验证还清**：5 个判据 TB 在 Vivado xsim 2023.1 上用同一份 TB、
同一套判据再跑一遍，全过，帧间间隔测量给出与 iverilog 完全相同的数值。
复现加 `--xsim` 即可。这是 1.0.0 签字里明记的短板，现已消除。

RTL 一个字节未改。

## [0.1.2] — 2026-08-04 复位/稳定性取证 + 可复现入口，只剩签字

新增三个 TB 与一个复现入口，G-C-04 / G-C-05 / G-GATE-02 全部通过。
**本包现在只卡在 G-SIGN-01（owner 签字）。**

**G-C-04**（`tb_cp_remove_reset`）：帧中途拉复位并保持 3 拍，对 8 个受复位寄存器
逐项比对复位值。数据通路的 3 个寄存器（`ri_data` / `ro_re` / `ro_im`）按设计不复位，
单列并**断言它们在复位期间仍跟随输入**——若将来有人给它们加了复位，比对表会与设计
脱节，这条会先失败。另验证复位释放后能重新起窗。

**G-C-05**（`tb_cp_remove_stability`）：boundary / stress / backpressure 三个子结果
实跑，regression 由 `run_sim.cjs` 从判据 TB 的实跑结果合成，不手写。

**G-GATE-02**：`run_sim.cjs` 跑全部 5 个 TB，`--install` 由实跑结果落证据。
任一 TB 不过即整体失败且**不写任何证据**——半份证据比没有证据更危险。

### 刻画出两条此前未知的接口约束

写 stress 场景时 12 帧背靠背只出了一半的点，查下去发现是真的：

1. **帧间必须至少隔 1 个样点**。零间隔时 `fft_start` 与 `S_DATA → S_UNSYNC`
   同拍到达被吞，整帧丢失。逐值测出来的（`tb_cp_remove_gap`：gap=0 出 0 点，
   gap≥1 出 256 点），不是读代码猜的。
2. **`i_cfg_n_sym` 必须 ≥ 1**。n_sym=0 时 RTL 仍吐 1 个数据符号（192 点），
   而 golden 只出 2 个 LTS（128 点）。

两条在集成中都不会触发（`sync_top` 单突发，帧间必有复位），但契约必须写明。
都记进了 `docs/limitations.md` §5/§6，并且 stress 段用断言把零间隔的行为**锁住**——
将来有人改 FSM 让零间隔也能起窗，测试会失败并提示更新文档。

没有为此改 FSM：帧尾与起窗语义是需求门禁裁定过的，改它要走门禁而不是顺手改。

## [0.1.0] — 2026-08-04 首次入库（intake）

M1 关键路径第二件。需求门禁六维齐备（记录见 `var/gates/requirements-gate.json`），
golden 先行、RTL 后写。

**功能**：按 802.11a 帧结构在 `sync_top` 的样点流上切窗——`i_fft_start` 起
T1(64) → T2(64) → {跳16 取64} × `i_cfg_n_sym`。纯选通与计数，无算术、无存储。

**两项裁定落地**（owner 2026-08-03）：

- 帧尾由 `i_cfg_n_sym` 侧带静态给定，与决策⑧（PLCP 在范围外、rate/length 侧带
  静态给定）一致。备选的"自由流转到复位"会在帧尾后把噪声当符号吐给下游。
- `frame_start` 的延迟对齐**不由本模块承担**，改由 `fft64_sdf` 透传侧带——延迟
  天然匹配，不依赖任何人手算拍数。本模块只负责在 T1 首点打一拍 `o_sb`。

**帧结构取自库内 golden 而非记忆**：`models/comm/synch/config.m` 与
`generate_preamble.m`（引 IEEE 802.11a-1999 §17.3.3）给出 STS=10×16、GI2=32、
T1=T2=64、数据符号=CP16+64。GI2 由 `sync_top` 在上游消化（ADR-003：其
`o_fft_start` 与 T1 首样点同拍），故本模块从 T1 起算。

**验证**：

- `tb_cp_remove` — 切窗序列 / 帧尾 / 侧带 / UNSYNC 静默 / 复位重入，全过
- `tb_cp_remove_cosim` — **对治理 golden `rx_cp_window` 0 失配**（初版 640 点，
  0.1.1 延长到 2176 点）

位真证据出自 `models/comm/ofdm` 的治理资产，非暂存副本。

**一处在验证中被抓出的时序约定错误**（已修正）：初版让状态机的 `r_state` 描述
"上一拍"，却拿它判定当前寄存的样点——`i_fft_start` 那一拍 `ri_data` 已是 T1[0]
而 `r_state` 仍在 UNSYNC，导致 T1[0] 被丢弃，并连锁使 CP 段判断错位、多吐一个
符号。重写为 `w_seg`/`w_idx` 描述**当前样点**、`r_seg`/`r_idx` 为其寄存版，
约定写进模块头注释。这类"差一拍"在纯选通逻辑里不会让波形明显出错、只是整体
平移，TB 用样点值编码输入下标才使其一眼可读。

**本版未做**：综合取证、复位/CDC 证据、边界/压力/回归四子结果、签字。
（综合取证与 bit-true 证据已在 0.1.1 补齐。）
