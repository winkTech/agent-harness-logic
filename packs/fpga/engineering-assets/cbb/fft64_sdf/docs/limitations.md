# fft64_sdf — 已知限制与验证边界（1.0.1）

各条来自实测与设计裁决，非推测。证据见 README §3 与本包 `sim/` 的运行日志。

---

## 1. 内部 s21 是必需的，且**没有富余**

满幅 Q2.14 输入下，级 6 移位前的逐轴上界为 `16·max|x| = 45.25`（两轴同时满幅时
的模），超出 s20 的 ±32。按 64 个输出 bin 逐个做对抗构造搜索（每个样点按该 bin
的旋转角反挑两轴符号），最坏 **40.71**，确实回绕。s21 的 ±64 覆盖可证上界，裕量
1.41×。

**这不是理论洁癖**：满幅单音的逐轴峰值就是 31.999，对 s20 而言零裕量——一个满幅
CW 干扰单独存在就把裕量吃光，再叠加有用信号即溢。而溢出是回绕不是饱和，表现为
偶发且难复现的错误。

真实 OFDM 信号峰值仅 3.6~4.7；随机满幅顶点搜索 400 次最大 17.10。**风险来自结构化
信号，不是随机满幅。**

## 2. 输入必须已被 AGC 缩到不削顶

理想 OFDM 时域峰值 2.64 > Q2.14 的 ±2（PAPR 9.1~9.3 dB）。本模块假定上游已把
信号缩到不削 Q2.14。该假设**不由本模块检查**。

相关：`ofdm_tx_top` 的输出是 **Q3.13** 时域。M3 的 phy_loopback 若把它直接接进
本模块的 Q2.14 输入，真实信号尚有 3.4~4.5× 裕量不会炸，但病态输入（直流偏移、
单音）会溢——**环回集成必须显式插入 Q3.13→Q2.14 定标级**。

## 3. 对拍向量的字序与 cp_remove 相反

本包 TB 用 `{re[31:16], im[15:0]}`，`cp_remove` 用 `{im, re}`。写反了**不会报错**，
只会看起来像"变换方向算反了"——交换 re/im 等价于 `z → j·conj(z)`，失配模式与频点
反转 `X[k] → X[-k]` 极像，且 bin0/bin32 这两个不动点恰好仍匹配，更像真的方向错。

2026-08-04 重生成向量时踩过一次：误判为 RTL 方向缺陷，靠"与浮点 FFT 对比"这一步
独立判据才拆穿。改字序后重推的期望值与原向量**逐字节相同**。

## 4. 无反压契约（弹性缓冲的必要性已被实测修正）

上下游（cp_remove、core、reorder）均无 `ready`，本模块不可被停顿。下游
`channel_est_top` 确实**会**拉低 `s_axis_tready`（帧起始待决时、数据符号末 3 拍
窗口且 CPE 链未闲时）。

0.1.x 曾据此写下"两者之间必须有弹性缓冲，是 M1 硬依赖"。**2026-08-04 实测推翻了
这个推断**：在 `cp_remove → fft64_sdf → channel_est_top` 真实链路上（xsim，两帧
背靠背，中间放理想无限深 FIFO 观测），

| 场景 | 反压总拍 | 最长连续 | 缓冲峰值占用 |
|---|---|---|---|
| 真实 M1 链路（每符号 64 有效 + 16 拍 CP 空档） | **0** | 0 | **1** |
| 对抗：去掉 CP 间隙，背靠背连续符号 | 22 | 4 | **23** |

**802.11a 的 CP 每符号天然留出的 16 拍空档，就是 `channel_est_top` 需要的全部弹性**
——包括第二帧起始那条 `w_stall_frame` 路径，实测也从未触发。

所以：M1 配置下**不需要**弹性缓冲。但这个结论**依赖 CP 间隙存在**——若上游节奏
改变（例如换 profile 或 fft64 被喂以连续流），实测上界是 **23 个条目**。

**这条风险已有具名承接点**：链路里紧接本模块的 `cbb/sb_align`（1.0.0）本就带一个
深度可配的缓冲，届时把它的 `P_DEPTH` 调到 32 即可——不必新起件，也不必用库内
`axis_skid_buffer` / `stream_elastic_pipeline`（DEPTH=2，那种情况下不够）。

## 5. 尾部冲刷需继续馈**有效**拍

各级 FIFO 只在 `i_beat && w_v[SI]` 时移位，拉低 `i_valid` 不排空流水、只是把在途
样点冻在原地。流末须继续送 valid 的零样点。

另：连续多符号时**冲刷长度必须是 64 的整数倍**，否则 SDF 的块边界（按有效拍划分）
会错位。实测偏移 8 拍时表现为各 bin 幅度正确但相位按 −45°/bin 线性旋转、直流
bin0 只剩 1/4——这个相位特征可用于反查偏移量。

**冲刷量已由 `tb_fft64_tail` 钉成契约数：撤 `i_valid` 后恰好卡住 1 个符号，
补 64 拍有效零样点即全部排空。** 该 TB 双向断言（不补就必须丢、补 1 个就必须
全出），谁改了流水让它自排空，测试会失败并提示更新本节。

**这一条在 M1 链路上是个真实的功能洞**：帧结束后 `cp_remove` 转 UNSYNC 静默，
fft64 再也收不到有效拍——每帧稳定丢最后一个数据符号。整条链路里目前**没有任何
人负责补这个冲刷**（2026-08-04 用 `cp_remove → fft64_sdf → channel_est_top` 实链
在 xsim 上实测：`TAIL_STUCK 64` 样点）。责任方待需求门禁裁定。

## 6. 首个符号会带出未初始化值

FIFO/数据流水按设计不复位（利于 BRAM/SRL 宏吸收）。复位后第一个符号的输出包含
未初始化值，须先送一个符号预热。TB 与集成方都要遵守。

## 7. 侧带的语义边界

`o_sb` 只保证与本符号**首个输出**同拍，不携带任何帧内容。它的用途是让
`frame_start` 穿越本模块后仍与它所标记的符号对齐。侧带宽度为 1 bit，不可承载
多位信息。

## 8. 验证边界

已证：结构（冲激/直流/Nyquist）、方向可分辨性（复数单音）、输出序、侧带对齐、
对**治理** golden 镜像的 2560 样点 bit-true（G-B-03），
OOC 综合后的时序与资源（G-C-01/02，见 CHANGELOG 0.1.1），
流水灌满后复位的 **41 个受复位寄存器逐项比对**（G-C-04），
以及 boundary / stress / backpressure / regression 四个子结果（G-C-05）。

其中 **boundary 是第 1 条那个 s21 结论的实测支撑**：满幅 Q2.14 直流下 bin0 理论值
`8x` 远超 s16，实测饱和到 +32767 而非回绕成负数。此前只有对抗构造的解析上界。

**未证**：板级验证。

**第二仿真器交叉验证已还清**（1.0.1）：全部判据 TB 在 Vivado xsim 2023.1 上用
**同一份 TB、同一套判据**再跑一遍，结果与 iverilog 一致。复现：给本包的
`run_sim.cjs` 加 `--xsim`。本机 ModelSim 回环 RPC 自 2026-08-01 起故障，那条路仍不通。

`P_DIR=1`（IFFT）配置仅由方向专项 TB 与解析判据覆盖，**未做该方向的 bit-true
对拍**——现有向量是正向的。若要把本核回切给 `ofdm_tx_top` 复用，须先补 IFFT
方向的 0 容差对拍。
