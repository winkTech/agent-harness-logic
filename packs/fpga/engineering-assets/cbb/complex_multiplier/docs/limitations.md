# complex_multiplier — 已知限制（1.0.0）

以下各条来自实测与设计裁决，非推测；验证证据见
`engineering-assets/evidence/complex_multiplier/1.0.0/`。

1. **全精度输出，不做舍入/饱和（刻意决策）**：输出位宽 `P_A_W+P_B_W+1`
   （16×16 时 **33 位**），定标语义**交调用方**。这是为避免重蹈库内 4 套互不
   相同定点语义（rrc/ldpc/channel_est/cn_update）的覆辙而定的约定。使用方必须
   自行处理截位与定标；直接把 33 位接到 16 位端口会静默截断。
   数学上不可能溢出：`|re| ≤ 2·2^30 < 2^32`。

2. **无反压接口**：定长 **3 拍**延迟流水，不带 `tready`。需要背压时在**输出侧**
   例化已认证的 `axis_skid_buffer`。G-C-05 的 backpressure 子结果按「随机 valid
   图样下 `o_valid` 与参考模型期望 valid 链逐拍严格对齐」的等价判据取证。

3. **数据通路自由流水**：数据级不由 `valid` 门控，无效拍的数据仍被计算，仅由
   valid 链标记有效性 —— 与 `rrc_polyphase_fir` 一致的约定，避免使能链成为时序
   瓶颈。**功耗敏感场景需另行评估**（无效拍仍触发 DSP 翻转）。

4. **四乘法直算，非三乘法**：Gauss/Karatsuba 三乘法可省 1 个 DSP，但引入额外
   加法器与位宽增长。在无实测资源压力前不做该优化 —— 四乘法映射直观、位宽推理
   无歧义。

5. **DSP 用量与位宽绑定**：默认 16×16 落在 DSP48E1 的 25×18 内，每乘法独占
   一片，**实测 DSP = 4**。更大位宽会拆成多片级联，资源与时序均需重新评估。
   综合与预算均按默认参数取证。

6. **与旧模板不兼容（breaking）**：改写自
   `skills/hdl-coding/templates/comm/cmult.sv` v1.0.0。原件 SKILL.md 标称"符合
   规范"，实测有 **4 条独立功能性错误**：公式写成 `re = ac+bd`（正确为 `ac-bd`）、
   操作数张冠李戴、死寄存器、跨级错拍且违反输入寄存红线。逐条记录在 RTL 模块头。

7. **综合口径**：WNS/资源来自 **OOC 综合**（`xc7k325tffg900-2`，仅
   `create_clock`），未做布局布线与 I/O 绑定。实测 LUT 0 / FF 3 是 DSP48E1
   完美吸收的结果（输入寄存→A/B 寄存器、乘积→M 寄存器、加减→后加器与 P 寄存器
   级联），fabric 侧只剩 3 拍 valid 链；集成到大设计后综合器的吸收决策可能变化。

8. **工具链**：本版全部仿真证据由 **Vivado xsim 2023.1** 产出（本机 ModelSim
   回环 RPC 故障）；`vlog` 编译不受影响，门禁 G-A-00 仍由 ModelSim 判读。
