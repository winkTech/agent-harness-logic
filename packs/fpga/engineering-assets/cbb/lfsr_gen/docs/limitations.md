# lfsr_gen — 已知限制（1.0.0）

以下各条来自实测与设计约定，非推测；验证证据见 README「验证」与
`engineering-assets/evidence/lfsr_gen/1.0.0/`。

1. **周期性质仅在两组多项式上实测锚定**：16 位 `16'hB400`（周期 65535）与
   7 位 `7'h60`（周期 127）。其他 `P_POLY` 配置的本原性与周期**未逐一验证** ——
   使用方更换多项式时须自行确认其为本原多项式，否则周期会短于 `2^W-1`。

2. **非密码学安全**：Fibonacci LFSR 输出是线性可预测的伪随机序列，观察到
   连续 `P_WIDTH` 个输出即可反推全部后续状态。**不得用于密钥流、鉴权或任何
   安全场景**；仅适用于扰码、PRBS 测试图样、白噪声激励。

3. **参数约束（违反即失效，RTL 不做运行时检查）**：
   - `P_SEED` 全 0 非法 —— LFSR 进入死态，永远输出 0。
   - `P_POLY[P_WIDTH-1]`（x^P_WIDTH 项）**必须为 1**，否则实际反馈多项式
     阶数低于标称。
   - 抽头约定：`P_POLY[e-1] = 1` ⇔ 多项式含 `x^e` 项。该约定与部分教材的
     位序相反，接线前务必核对（例：`7'h60` 是 x^7+x^6+1，而 `7'h41` 是
     x^7+x^1+1）。

4. **与旧模板序列不兼容（breaking）**：改写自
   `skills/hdl-coding/templates/comm/lfsr_gen.sv` v1.0.0，原件反馈掩码写作
   `POLY[WIDTH-2:0]` 截掉了 x^WIDTH 主抽头，序列与周期均不符标称。本模块修复
   后序列与旧模板**不同** —— 旧序列本身是错的，不存在兼容性义务。原件的 4 条
   缺陷逐条记录在 RTL 模块头。

5. **无反压接口**：仅有 `i_en` 推进使能，无 ready/valid 握手。下游必须能在
   `o_valid` 拍无条件接收；需要弹性的集成方在下游接已认证的
   `axis_skid_buffer`。G-C-05 的 backpressure 子结果按「任意使能图样下
   `o_valid` 拍数严格等于被采纳的 `i_en` 拍数」这一等价判据取证。

6. **时序契约**：`i_en` 置位后 **2 拍**（输入寄存 + 输出寄存）`o_valid`/`o_data`
   有效；每个被采纳的 `i_en` 拍恰好产出一个字。复位期间及撤销使能期间状态冻结、
   不产出。

7. **综合口径**：WNS/资源来自 **OOC 综合**（`xc7k325tffg900-2`，仅
   `create_clock`），未做布局布线、未做 I/O 绑定，按默认参数 `P_WIDTH=16`
   评估。更大位宽会线性增加 FF 并加深异或树，需重新评估。

8. **工具链**：本版全部仿真证据由 **Vivado xsim 2023.1** 产出。本机 ModelSim
   10.6c 的回环 RPC 故障使其无法加载设计；`vlog` 编译不受影响，门禁 G-A-00 仍
   由 ModelSim 判读。
