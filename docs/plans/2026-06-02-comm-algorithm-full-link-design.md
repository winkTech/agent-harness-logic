## 概述

为通信算法 FPGA 实现建立标准化全链路流程，覆盖从算法分析到最终报告输出的完整生命周期。每个环节产出可复用模板，所有环节串接形成闭环。

**预期收益:**
- 新算法实现周期缩短 40%+
- 定点量化有据可依，减少凭经验猜测
- 验证自动化，消除手工比对
- 交付文档自动生成，格式统一

---

## 一、框架总览

```
阶段1 [算法分析] ──→ 阶段2 [MATLAB浮点] ──→ 阶段3 [定点量化]
                                                    │
                                                    ▼
阶段7 [报告输出] ←── 阶段6 [功能验证] ←── 阶段5 [RTL实现] ←── 阶段4 [资源评估]
```

所有阶段串行依赖，不可跳越；若阶段5发现资源超标，回退阶段4或阶段3调整位宽。

---

## 二、阶段详解

### 阶段1：算法分析与文档化

**目标:** 在写任何代码之前，把算法的数学原理、参数空间、设计约束文档化

**输入:** 标准/论文/参考实现
**产出:** `algorithm_spec.md` + 参数表 (MD/Excel)

#### 子项

| 子项 | 内容 | 输出格式 |
|------|------|----------|
| 1.1 数学推导 | 算法核心公式、信号流图、关键变量定义 | Markdown + LaTeX |
| 1.2 参数分析 | 数据率、时钟频率、量化位宽需求、延迟约束 | 参数表 |
| 1.3 参考实现 | MATLAB/Python 参考代码结构分析，黄金参考定义 | 函数接口定义 |
| 1.4 设计约束 | 目标器件型号、可用资源、时序要求 | 约束检查表 |

#### 关键原则
- `algorithm_spec.md` 是整个项目的"宪法"，后续所有阶段决策必须能回溯至此
- 参数分析明确区分"必须满足"和"可以权衡"两类约束

---

### 阶段2：MATLAB 浮点模型

**目标:** 构建可运行的浮点黄金参考模型，产出测试向量供后续验证

**输入:** `algorithm_spec.md`
**产出:** `golden_model/` 脚本包 + 测试向量

#### 子项

| 子项 | 内容 |
|------|------|
| 2.1 模块化脚本结构 | 每个子功能独立函数，顶层脚本串接全链路 |
| 2.2 参数化配置 | 统一 `config.m` 管理所有参数 |
| 2.3 测试向量生成 | 多种模式（CW、随机数据、边界条件），导出 `.txt/.bin` |
| 2.4 性能基线 | 浮点 BER/EVM 曲线，作为定点退化基准 |
| 2.5 自检脚本 | `run_all_tests.m` 一键运行所有测试，输出 PASS/FAIL |

#### 关键原则
- MATLAB 模型是"真理源"——RTL 仿真以它的输出为比对标准
- 测试向量覆盖：常规数据、边界值、特殊模式
- 信号命名与后续 RTL 保持一致

#### 目录模板

```
golden_model/
├── config.m               # 参数配置
├── run_all_tests.m        # 一键运行
├── src/                   # 函数源码
│   ├── tx_chain.m         # 发射链路
│   ├── rx_chain.m         # 接收链路
│   └── utils/             # 工具函数
├── tests/                 # 测试用例
│   ├── test_modulation.m
│   └── test_channel.m
├── vectors/               # 测试向量输出
│   ├── tx_data.bin
│   └── rx_data.bin
└── results/               # 性能结果
    └── ber_curve.mat
```

### 阶段3：定点量化

**目标:** 确定每个节点的位宽，在资源与精度之间找到最优折中

**输入:** 浮点模型 + 测试向量
**产出:** `fixed_point_report.md` + 定点 MATLAB 模型

#### 子项

| 子项 | 内容 |
|------|------|
| 3.1 位宽扫描 | 各节点从高到低逐级缩减位宽，观察 BER/EVM 退化 |
| 3.2 溢出分析 | 统计各节点动态范围，确定整数位宽 |
| 3.3 截断/舍入策略 | 比较 truncation/rounding/saturation 效果 |
| 3.4 定点模型 | `fi()` 重构，bit-true 对标浮点基线 |
| 3.5 量化误差报告 | 各节点 SNR 退化、最大误差、MSE 汇总 |

#### 关键原则
- 定点模型必须 **bit-true**——与 RTL 逐比特一致
- 位宽决策有量化证据支撑
- 优先保关键路径（反馈环路、误差敏感节点）

---

### 阶段4：资源评估

**目标:** 评估 DSP/LUT/BRAM 消耗，给出架构缩放建议

**输入:** 定点位宽表 + 目标器件型号
**产出:** `resource_estimate.md`

#### 子项

| 子项 | 内容 |
|------|------|
| 4.1 DSP48 映射表 | 每个乘/加运算位宽 → 拆分为 N 个 DSP48 的详细映射 |
| 4.2 架构缩放选项 | 全并行 / N路时分复用 / 全串行的资源与吞吐对比 |
| 4.3 资源预算 | 目标器件总量 vs 预估消耗，裕量百分比 |
| 4.4 瓶颈识别 | 最大消耗模块，评估替代方案 |
| 4.5 替代映射 | 何时用 LUT+寄存器替换 DSP48 |

**示例输出：**

| 模块 | 位宽 | 运算 | DSP48 | LUT | BRAM |
|------|------|------|-------|-----|------|
| IFFT | 16bit | 复数乘 | 12 | 2400 | 4 |
| 调制映射 | 8bit | LUT | 0 | 128 | 1 |
| 成形滤波 | 16bit | MAC×32 | 16 | 3200 | 0 |
| **总计** | | | **28** | **5728** | **5** |
| 目标(XC7K325T) | | | 840(3%) | 203800(3%) | 445(1%) |

### 阶段5：RTL 架构实现

**目标:** 基于定点和资源评估，编写可综合 RTL

**输入:** 定点模型 + 资源评估
**产出:** RTL 源码 + 时序约束

#### 子项

| 子项 | 内容 |
|------|------|
| 5.1 模块划分 | 模块接口定义、数据流图、AXI4-Stream 握手协议 |
| 5.2 流水线设计 | 延迟拍数、寄存器插入、路径平衡 |
| 5.3 控制逻辑 | 状态机、使能信号、复位策略 |
| 5.4 时序约束 | 时钟域定义、I/O延迟、虚假路径 |
| 5.5 可配置性 | parameter 支持多种模式 |

#### 目录模板

```
rtl/
├── src/
│   ├── <module_name>.v
│   └── <module_name>_ctrl.v
├── constraints/
│   └── <project>.xdc
└── ip/
    └── <ip_core>.xci
```

### 阶段6：功能验证与覆盖

**目标:** 自动化验证 RTL 与定点模型 bit-true 一致

**输入:** RTL 源码 + MATLAB 测试向量
**产出:** Testbench 套件 + 覆盖率报告

#### 子项

| 子项 | 内容 |
|------|------|
| 6.1 自检 Testbench | 读入向量 → 驱动 DUT → 自动比对 → PASS/FAIL |
| 6.2 逐级验证 | 子模块独立验证 + 集成验证 |
| 6.3 边界注入 | 溢出/饱和/全0/全1/复位抖动 |
| 6.4 覆盖率统计 | toggle/line/branch + 功能 covergroup |
| 6.5 自动化回归 | Tcl 脚本一键跑完 |

#### 目录模板

```
sim/
├── tb/
│   ├── tb_<module_name>.sv
│   └── tb_top.sv
├── tests/
│   ├── test_normal.m
│   └── test_boundary.m
├── scripts/
│   └── run_regression.tcl
└── results/
    └── coverage.rpt
```

### 阶段7：报告输出

**目标:** 将前6阶段成果自动组装为交付文档

**输入:** 前6阶段全部产出
**产出:** 技术报告 + PPT + Word

| 输出类型 | 工具路径 | 内容 |
|----------|----------|------|
| 技术报告(MD) | doc-generator | 全阶段内容合并 |
| PPT | pptx skill | 背景→原理→架构→资源→验证→总结 |
| Word | markitdown→pandoc/docx | MD 转 Word |

**PPT 结构（10-15页）:**
封面 → 背景需求 → 算法原理 → 架构图 → 定点策略 → 资源评估 → 模块划分 → 流水线 → 验证方案 → 验证结果 → 总结 → 下一步
