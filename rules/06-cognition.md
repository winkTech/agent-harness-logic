# 认知层 — 7 种推理模式（详细参考）

> **模式切换条件已在 `00-core.md`（L0，始终加载）中定义。**
> 本文件是七种模式的详细参考，不直接参与触发判断。
>
> 核心原则：**失败是系统级信号，应触发模式切换，不是给模型加压。**
> 与 PUA 话术的根本区别：PUA 在所有场景等价施压，认知层只在挫败信号确凿时切换。
>
> 挫败信号 = 用户说"再试试"/"不对"/"又错了" — 这些话语不带新约束，
> 意味着上一轮的方案没形成有效反馈 = 当前推理范式失败的确定信号。

## 七种模式

### 1. 根因分析 (Root Cause Analysis)
- **适用**: 修 bug、查事故、调试
- **方法**: 5-Why 追问 + 扫同类 bug 模式
- **输出**: 根因陈述 + 修复方案 + 同类预防

### 2. 第一性原理 (First Principles)
- **适用**: 新建功能、设计方案、从零开始
- **方法**: 质疑假设 → 删除非本质 → 简化 → 加速 → 自动化
- **输出**: 最小可行方案 + 递进优化路径

### 3. 减法 (Subtraction)
- **适用**: 重构、清理、技术债还债
- **方法**: 删除优先，不增加新抽象。问"不做什么"
- **输出**: 删减清单 + 合并/简化建议

### 4. 搜索优先 (Search First)
- **适用**: 根因未知、问题领域不熟、有"我好像见过"
- **方法**: 先查历史/文档/代码索引，再判断。不猜测
- **检索工具链**:
  - `grep` — 精确字段名/URL/环境变量
  - `semantic-search` — 跨词同义+"记得有个决策关于..."
  - `code-graph` — 调用链/import 关系
  - `git log` — 谁何时改过
- **输出**: 检索结论 + 下一步判断

### 5. 倒推 (Working Backwards)
- **适用**: 新模块设计、接口定义、需求不明确
- **方法**: 从用户终态倒推 → 写 PR 稿/使用示例 → 再确定接口 → 最后实现
- **输出**: 用户场景描述 → 接口定义 → 实现计划

### 6. 证据驱动 (Evidence-Driven)
- **适用**: 性能优化、质量评估、方案选型
- **方法**: 用测量数据替代直觉。先 baseline，再改，再测
- **输出**: 基准 + 对比数据 + 结论

### 7. 闭环 (Closed Loop)
- **适用**: 默认模式、部署、运维、多步骤任务
- **方法**: 定目标 → 追过程 → 拿结果 → 复盘
- **输出**: 进度报告 + 下一步 + 完成检查

## 自动切换规则

### 触发条件
当以下任何信号出现，必须在响应开头声明模式切换：

| 信号 | 命中后建议切换 |
|:----|:--------------|
| "不对" / "又错了" / "还是不行" | → 根因分析 |
| "再试试" / "换一种方法" | → 搜索优先（查同类方案） |
| "太复杂" / "精简一下" | → 减法 |
| "从用户角度" / "预期行为" | → 倒推 |
| "测一下" / "数据呢" | → 证据驱动 |
| "卡住了" / "绕圈" | → 第一性原理（质疑所有假设） |
| 无特殊信号 | → 闭环 |

### 切换声明
切换时必须明确输出：
```
🔄 切换到 [模式名] 模式
原因：检测到 [信号]，当前 [原模式] 未产生有效进展
```

### 状态持久化
切换后更新运行时状态：
```bash
node ~/.claude/engine/scripts/runtime-state.cjs set-mode <模式名>
node ~/.claude/engine/scripts/runtime-state.cjs bump-failure  # 如果原模式失败
```

## 与 L2 记忆层的配合

- 搜索优先模式 自动触发 `memory-retrieve.sh` + `semantic-search.cjs` 检索
- 根因分析模式 自动查阅 `memory/errors/` 中的同类错误
- 证据驱动模式 自动调用性能监控脚本
