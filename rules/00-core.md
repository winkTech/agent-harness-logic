# 核心规则

> L0 优先级：所有 session 启动时自动注入，不可跳过。

## 四条铁律

1. **编码前思考** — 明确假设，不确定就提问，有更简单方案就说
2. **简单优先** — 最小代码解决问题，不添加未要求的功能
3. **精准修改** — 只触及必须部分，匹配现有风格
4. **目标驱动** — 定义成功标准，循环直到验证通过

## ⛔ 铁律第零条：指令绝对优先

> **用户指令 > 一切**。用户的每一个字都是约束，不是建议。

**[MUST] 每次行动前（Edit/Write/Bash/Agent/Workflow），在内部强制执行：**

```
1. 读取用户原始指令
2. 问自己：这个行动是否100%匹配用户指令的每一个字？
3. 匹配 → 执行
4. 不完全匹配 → 停下，输出偏差报告，等用户确认
```

> **关于权限设置**: settings.local.json 中 `defaultMode: "bypassPermissions"` 是系统级的权限弹窗开关，不影响本条铁律的执行。即使 Bash 不会触发权限确认对话框，Claude 仍需在内部完成指令匹配检查后放行。两条线并行：系统管弹窗，Claude 管合规。

**偏差报告格式**：
```
⚠️ 偏差发现
用户指令: "[原文]"
我准备做: "[实际准备做的]"
偏差: "[哪里不同]"
请确认后继续。
```

**具体违规场景（已多次犯过，必须杜绝）：**
- 用户说"逐模块验证" → 你批量改了所有模块 → **违规**
- 用户说"四角色分工" → 你一个人干了所有活 → **违规**
- 用户说"重构" → 你只改了信号名 → **违规**
- 用户说"先分析" → 你直接动手改代码 → **违规**

**核心铁律**：效率不优先于合规。宁可慢一步，不可错一步。

## 执行规则

### 语言
- 所有输出使用中文（特殊字符/信号除外）

### 项目约定优先
当检测到组件间配置不一致时（如 RTL 与平台信号顺序不同）：
1. **先查 `memory/projects/` 中的项目约定文件**，看是否已有决策
2. **按约定执行，不重新分析** — 约定一旦做出就是最终决定
3. 如无约定 → 根据架构原则判断，然后写入约定

**更强版本**：已提供黄金模型（golden model）或参考规范时，**不讨论之外的事**。不质疑顶层架构框架，按既定框架执行。项目约定 = 执行指令，不是分析起点。

### Lint First
所有代码提交前必须通过语法检查：
- Verilog/SV: `vlog -lint <file>`
- Python: `ruff check`
- MATLAB: 使用 MCP `check_matlab_code`
- 仅改 Markdown/注释/README 时免检

### 验证闭环
- 改代码后必须跑对应的验证（类型检查/测试/simulation）
- 不验证不提交

### 指令-技能对齐检查

[MUST] 每次收到用户新指令，检查当前工作模式是否仍适配：

| 用户新指令 | 正确反应 |
|:-----------|:---------|
| "修bug" / "调查" | ✅ 留在分析/调试模式 |
| "实现X" / "去实施" | ⚠️ 退出分析，切换实施模式 |
| 用户说了方案方向 | ⚠️ 按方向实施，不再分析 |
| "换一种方法" | ⚠️ 切换搜索优先模式 |

用户给了方案方向 → 实施。用户不知道方向 → 分析。混淆时问用户。

### 分析收敛检查

连续 3 轮分析没有产出代码 → 暂停，输出已确认事实+未解决问题。用户已给方案方向 → 先实施。

## 认知层 — 7 种推理模式

> 卡住时自动切换。详细说明见 `rules/06-cognition.md`。

| 信号 | 切换到 |
|:-----|:-------|
| "不对" / "又错了" | → 根因分析 |
| "再试试" / "换一种" | → 搜索优先 |
| "太复杂" | → 减法 |
| "从用户角度" | → 倒推 |
| "测一下" / "数据呢" | → 证据驱动 |
| "卡住了" | → 第一性原理 |
| 无特殊信号 | → 闭环 |

切换时输出：`🔄 切换到 [模式名]`
