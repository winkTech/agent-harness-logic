# mod_demapper CHANGELOG

## 1.0.1 — 2026-08-09（harness 修复，RTL 与判卷结果一字未改）

**RTL / 向量 / 判卷数字全部不变**，改的只有 `run_sim.cjs`。owner 2026-08-09 批准按
patch 处理、不重新签字；1.0.0 的 signoff 记录原样保留。

### ① `--xsim` 在 Windows 上根本没跑起来

`xsim` 是批处理包装器，转发 `-testplusarg NAME=VALUE` 时会**把 `=` 吃掉**，xsim 报
`Expected a switch but found <值>` 打印 usage 退出。只有本件受影响——库里另外四个
harness 不用 plusarg（只有本件要按调制跑三遍）。改为用 xsim 的 `-f` 选项文件传参。

**这个缺陷比"跑不了"更坏**：三档顶层 TB 被记成 `pass:false, judgements:0`，而在证据
文件里，它与"跑了但没过"长得一模一样。1.0.0 认证时只有 iverilog 一件证据，正是因为
这个——**不是 xsim 判出了不同结果**。

### ② `--install` 会把"没跑起来"当成合法结果落盘

修好 ① 之后补的守卫：任一 suite 的 `judgements === 0` 即拒绝落盘、退出码 2（与真实
失败的 1 区分），并打印该 suite 的真实工具输出。

不这么做的话，一次工具链故障就能把 `pass:false` 写盖掉已封存的好证据，而排查方向
完全不同：工具坏了要修工具，RTL 回归了要查 RTL。

这不是新规矩——库内 `cp_remove` / `fft64_sdf` / `sb_align` 三件本来就这么做
（`!registers.length` → "复位 TB 没有产出 RESET_REG 行" 直接退出；`!stab[k]` →
"未产出子结果" 直接退出）。本件与 `eq_zf` 是仅有的两个漏掉它的包，1.0.1 补齐。

### 实测

- **守卫经过实证会触发**：临时移走 `tb/tb_demap_metric.sv` 使其编译失败，`--install`
  如实报出 "未产出任何判据行，判定为**未跑起来**"、打印 iverilog 的真实报错、拒绝
  落盘；已封存证据未被改动（复验仍 `pass=true / 30749`）。**加了守卫不验它会不会
  触发，就又是一条空转判据。**
- **`--xsim` 端到端跑通**：6/6 PASS，`tool = "Vivado xsim 2023.1"`，30749 次比对，
  三档 27648 个 LLR **0 失配**，T8 吞吐拍数与 iverilog **逐拍相同**（16122/16124/16126）。
  至此本件的判卷有两件独立仿真器背书，与 `eq_zf` 同一标准。

## 1.0.0 — 2026-08-06（首版，intake）

软判决解调 (max-log LLR)，三档调制，Q(10,4) 串行输出。位真基准是治理侧
`models/comm/ofdm/src/rtl_mirror_demap.m`（models 1.8.0 入库），判卷 **0 容差**。

### 立件动因

跨已认证资产的契约缺口：`cbb/ldpc_codec` 吃 LLR Q(10,4) + 归一化 Min-Sum，而
`models` 侧的 `mod_demapper.m` 出的是**硬比特**——硬比特喂不进软译码器。

### 实测定案（每个常数都有出处，没有一个是"看着合理"定的）

| 项 | 取值 | 判据 |
|---|---|---|
| 结构 | 按 I/Q 轴分解，每轴 √M 电平 | 前提"比特标号也按轴划分"**查出来的**，分解式对锚偏差 2.66e-15 |
| 标度 K | 2 / 16 / 32 | **端到端 BER** 穿真实 LDPC 译码器；代理指标定不了 |
| conf | 6 位尾数 + 6 位指数 | LLR 相对误差 0.0027，在 Q(10,4) 自身量化误差 0.005 的一半以下 |
| 定标 | `sh' = 67 - sh - log2K` | 整数通路对浮点锚最大 1.00 LSB、>1LSB 占 0% |

**K 必须分档**，代价高度不对称：64QAM 误用 K=2 时 BER 由 3.09e-05 恶化到 0.0902（约
3000 倍），而 QPSK 误用 K=32 仅差 1.6 倍。

### 结果

- 判卷：三档合计 **27648 个 LLR，0 失配**；`run_sim` 六次实跑 **30749 次比对 / 57 条判据**
- 综合：WNS **+4.508 ns** @10 ns（≈181 MHz），WHS +0.123 ns，**0 失败端点**；
  LUT 2220 / FF 1044 / BRAM 0 / **DSP 18**
- 吞吐：**6.9 拍/点**（预算 8.33）
- 门禁：**21/22**，缺 G-SIGN-01（owner 签字）

### 开发过程中修掉的缺陷（都记在这，因为它们各自代表一类）

**① 定标常数首版写 42，差出 2²⁵。** 漏了 `d2` 是 Q4.12 的**平方**（2²⁴）与锚里的
`÷(2σ²)`（÷2）。在 incubator 原型上就现形（最大差 512 LSB、90% 的点超 1 LSB，荒谬到
一眼能看出）。若不先测就写进规格，RTL 会照抄，那时的现象是"LLR 全是饱和值"，排查方向
多半指向解调算法而不是定标常数。

**② `sh'` 上界是 66 不是 63，字段要 7 位。** 规格初版只算了合法 `sh∈[3,34]`，漏了
`conf=0` 的擦除哨兵；且值域**逐调制不同**。按 63（6 位）开会把 66 截成 2，深衰落载波
于是给出满量程乱数而不是 0。是**判卷向量的覆盖自查**撞出来的——镜像测试只随机
`sh∈[3,34]` 时实测停在 59，"规格写 63"看着毫无问题。**测出来的范围比真实范围窄**，
正是位宽错最爱藏的地方。

**③ 复位期间 `s_axis_tready` 恒为 1 → 数据静默丢失。** `~r_inflight & w_hold_free` 在
复位时两项都被清零。上游保持 tvalid 时握手成立、beat 被吃掉，而 `ri_valid` 被复位钳住
——**上游还以为发出去了**。三个功能 TB 全绿也没抓到：它们复位期间不驱动 tvalid。是列
复位寄存器清单时才看出来的。

**④ 数据通路全带了复位。** `r2_sq` / `r1_prod` 是乘法器输出寄存器，带复位会挡住 DSP
内部寄存器吸收（hdl §1.1）。改为控制受复位 / 载荷少复位后 DSP 恰好落在 18 个。拆的
时候一度只改了 else 分支、复位分支的赋值还留着，造成**同一寄存器被两个 `always_ff`
驱动**，被 T3 当场抓到。

**⑤ 参考模型自己溢出。** `tb_demap_scale` 首版用 64 位，`sh'=66` 时半量 2⁶⁵ 溢出成
负数，参考给 −1 而 DUT 给 0——**DUT 是对的**。改 96 位后 0 失配。参考模型必须有足够
余量才配当参考。

**⑥ 两条"判据看着过了其实空转"。** 复位 TB 的 T1d 首跑报 `ofifo[3]=0`：激励的 sh 取低
段使 LLR 恒 0，"复位后仍是 0"永远成立——判据没错，是激励没给出内容。另一条是
`run_sim.cjs` 里写过 `... || true` 的假边界检查，已删。

**⑦ 两个 TB 首版都没有看门狗，表现为挂死而不是失败。** 挂死要等外层超时才被发现且
日志无指向。两处都补了。

### 已知边界

见 README §5。最要紧的一条：**不支持 BPSK（D-DEMAP-01）**，而 802.11a 的 6/9 Mbps 就是
BPSK——这是对 Clause 17 的真实覆盖缺口，不是"暂未实现"。
