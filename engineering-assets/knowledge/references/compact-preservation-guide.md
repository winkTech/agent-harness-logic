# 上下文压缩保留指南

> 在 subagent 输出结果时，附带本条指引，帮助调度层在 `/compact` 时保留关键信息。

## 算法工程师 (algorithm-engineer)

算法工程师产出被压缩时，**必须保留**：

| 类别 | 必须保留 | 可丢弃 |
|:-----|:---------|:-------|
| 定点量化 | 位宽决策、误差指标(NMSE/SNR)、资源预算 | 逐位宽扫描的中间曲线 |
| Golden Model | 算法公式版本、关键参数、与 RTL 的接口约定 | 调试时的中间打印 |
| 架构方案 | architecture.yaml 的模块划分、流水线级数、握手协议 | 讨论过的备选方案（除非有记录价值） |
| 测试向量 | 向量覆盖类型（corner case 列表）、数量、格式 | 逐条向量的生成过程 |
| 差异分析 | Golden vs RTL 的差异根因、修复方向 | 来回调试的中间尝试 |

## 逻辑工程师 (logic-engineer)

逻辑工程师产出被压缩时，**必须保留**：

| 类别 | 必须保留 | 可丢弃 |
|:-----|:---------|:-------|
| RTL 实现 | 模块接口、关键 FSM 状态图、流水线结构 | lint 警告的逐条修复过程 |
| 验证证据 | 每个模块的 status=PASS、compared_points、max_error | 单次调试的波形截图描述 |
| 时序优化 | 关键路径、Fmax、时序裕量 | 逐级 pipeline 插入尝试 |
| 审查修复 | 审查发现的 BLOCKER/MAJOR 项及修复确认 | NIT 级别的格式调整讨论 |
| 集成联调 | 顶层模块结构、模块间接口连接 | 单模块编译错误的修复过程 |

## 通用规则

1. **文件路径** — 所有已修改/新建的文件路径必须保留
2. **待办** — 所有 P0/P1 待办事项必须保留
3. **决策** — 所有未写入正式文档的架构/算法决策必须保留
4. **差异** — Golden Model 与 RTL 的已知差异及其根因必须保留
5. **否定规则** — "约定不做的事"比"做了的事"更容易忘，所有禁止项（MUST NOT）必须保留
