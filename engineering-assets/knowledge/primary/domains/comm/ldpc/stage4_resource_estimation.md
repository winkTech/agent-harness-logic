# LDPC Min-Sum 译码器 FPGA 资源估算

## 1. 设计参数

### 1.1 码参数

| 参数 | 值 |
|:----|:--:|
| 码型 | 802.11n QC-LDPC, R=1/2 |
| N × K | 648 × 324 |
| 提升因子 Z | 27 |
| 基矩阵 mb × nb | 12 × 24 |
| H nnz | 2,376 |
| 行重 | 7~8 (avg 7.3) |
| 列重 | 2~12 (avg 3.7) |

### 1.2 定点格式

| | Q(10,4) 推荐 | Q(8,3) 最小 |
|:---|:---:|:---:|
| 总位宽 | 10 bit | 8 bit |
| 小数位 | 4 bit | 3 bit |
| 范围 | [-32, 32) | [-16, 16) |
| α_fixed | 12 | 6 |
| SCALE | 16 | 8 |

### 1.3 架构选择

**逐行串行 (Row-Serial) 架构**：
- 每次处理一个 H 矩阵行（1 个校验节点）
- 行内并行：同时处理该行的所有连接（7~8 个 VN）
- 适合资源受限的场景，12 层顺序处理

```
┌──────────────────────────────────────┐
│  P_ROM (12×24×5b)                    │
│  ┌─────┐                             │
│  │Addr │ → 行地址生成器               │
│  │Gen  │ → 列索引 + 移位值            │
│  └─────┘                             │
│         ↓                             │
│  ┌──────────┐   ┌──────────┐         │
│  │LLR_total │   │ L_r_old  │         │
│  │  BRAM    │   │   BRAM   │         │
│  │ 648×10b  │   │ 2376×10b │         │
│  └────┬─────┘   └────┬─────┘         │
│       │ 8路并行       │ 8路并行       │
│       ↓               ↓               │
│  ┌──────────────────────────┐        │
│  │  8 × L_q = LLR - L_r    │ 减法    │
│  │  8 × |L_q|, sign        │ 取绝对值 │
│  │  min1/min2 查找树       │ 比较    │
│  │  prod_sign (XOR tree)   │ 符号积  │
│  │  8 × α-scaling (移位加) │ 缩放    │
│  │  8 × VN update (加法)   │ 更新    │
│  │  8 × 饱和逻辑           │ 限幅    │
│  └──────────────────────────┘        │
│       ↓                               │
│  ┌──────────┐   ┌──────────┐         │
│  │LLR_total │   │ L_r_old  │         │
│  │  Write   │   │  Write   │         │
│  └──────────┘   └──────────┘         │
│                                       │
│  早停检测: syndrome == 0?             │
│  迭代计数器 + 控制状态机              │
└──────────────────────────────────────┘
```

## 2. 存储器估算

### 2.1 LLR_total (后验 LLR)

| 属性 | 值 |
|:----|:--:|
| 深度 | 648 |
| 位宽 (Q10,4) | 10 bit |
| 位宽 (Q8,3) | 8 bit |
| 总容量 (Q10,4) | 6,480 bit |
| 总容量 (Q8,3) | 5,184 bit |
| 访问模式 | 1 读 + 1 写 / 周期 (True Dual Port) |
| BRAM (36Kb) | **1 个** (18% 利用率) |

### 2.2 L_r_old (CN→VN 消息历史)

需要存储每个非零 H 矩阵位置的旧消息：

| 属性 | 值 |
|:----|:--:|
| 条目数 | 2,376 (H nnz) |
| 位宽 (Q10,4) | 10 bit |
| 位宽 (Q8,3) | 8 bit |
| 总容量 (Q10,4) | 23,760 bit |
| 总容量 (Q8,3) | 19,008 bit |
| 访问模式 | 读-修改-写 (每个连接) |
| BRAM (36Kb, Q10,4) | **1 个** (66% 利用率) |
| BRAM (36Kb, Q8,3) | **1 个** (53% 利用率) |

> **优化**: L_r_old 可按行分区存储。每行最多 8 个连接，8×10=80 bit/行，324 行 → 25,920 bit ≈ 1 BRAM。

### 2.3 H 矩阵存储

QC-LDPC 的结构特性允许**块级压缩存储**：

| 方法 | 位宽 | 总容量 |
|:----|:---:|:------:|
| 存储完整 P 矩阵 (12×24) | 5 bit/entry | **1,440 bit** |
| 存储每行连接表 (324行×8conn×7b col_idx) | 7 bit/col | ~18,144 bit |

**推荐**: 仅存储 P 矩阵（1440 bit ≈ 0.14 Kbit），用组合逻辑实时展开：
- 当前行号 r，计算所属块行 b = r / Z，块内偏移 o = r mod Z
- 对每个 P(b, j) ≠ -1：列号 = j×Z + mod(o - P(b,j), Z)

| 属性 | 值 |
|:----|:--:|
| P 矩阵 ROM | 1440 bit (LUT-RAM) |
| 地址生成 | 组合逻辑 (~50 LUT) |
| BRAM | **0** (无需 BRAM) |

### 2.4 存储器汇总

| 存储器 | 条目 | 位宽 | 总容量 | BRAM (Q10,4) | BRAM (Q8,3) |
|:------|:---:|:---:|:------:|:------------:|:------------:|
| LLR_total | 648 | 10/8 | 6,480/5,184 bit | 1 × 36Kb | 1 × 36Kb |
| L_r_old | 2,376 | 10/8 | 23,760/19,008 bit | 1 × 36Kb | 1 × 36Kb |
| P 矩阵 | 288 | 5 | 1,440 bit | — (LUT) | — (LUT) |
| **合计** | | | **~26.5 Kbit** | **2 BRAM** | **2 BRAM** |

> Xilinx 7-series: 36 Kbit/BRAM, 可用 18 Kbit 模式。实际使用 **2 个 BRAM**。

## 3. 运算单元估算

### 3.1 关键路径分析

每行处理的关键路径（1 个时钟周期）：

```
读取 LLR_total[8] → 减法 L_q = LLR - L_r_old → |L_q| → 
min1/min2 查找 (8路比较树, log2(8)=3级) → 
α 缩放 (乘法/移位加) → 加法 VN 更新 → 饱和 → 写回
```

### 3.2 比较器 (min1/min2 查找)

8 路输入，3 级比较树：

```
Stage 1: 4 pairs → 4 comparators
Stage 2: 4 winners → 2 comparators for min1, 2 comparators for min2  
Stage 3: 2 winners → 1 comparator for min1, 1 comparator for min2
```

| 单元 | 数量 | 位宽 | LUT/单元 | 总 LUT |
|:----|:---:|:---:|:-------:|:------:|
| 8-bit 比较器 | ~12 | 8~10 bit | ~8 LUT | ~96 |
| min1/min2 选择逻辑 | — | — | — | ~30 |
| **小计** | | | | **~130 LUT** |

### 3.3 α 缩放单元

Q(10,4): α_fixed = 12, 实现为 `floor(mv × 12 / 16)`

```
mv × 12 = mv × (8 + 4) = (mv << 3) + (mv << 2)
floor(result / 16) = result >> 4  (截断)
```

| 操作 | 硬件 | 数量 | LUT/单元 | 总 LUT |
|:----|:----|:---:|:-------:|:------:|
| mv << 3 | 布线 (移位) | 8 | 0 | 0 |
| mv << 2 | 布线 (移位) | 8 | 0 | 0 |
| 加法 (mv<<3 + mv<<2) | 10+10→11bit 加法器 | 8 | ~11 LUT | ~88 |
| 右移 4 位 | 布线 (截断) | 8 | 0 | 0 |
| **小计** | | | | **~90 LUT** |

> **注**: 使用 DSP48 可节省 LUT。在 DSP48 中实现：1 个 DSP 可完成 25×18 乘法，8 个连接各需 1 个 DSP → **8 DSP slices**（或都不使用，纯 LUT）。

### 3.4 VN 更新单元

| 操作 | 硬件 | 数量 | LUT/单元 | 总 LUT |
|:----|:----|:---:|:-------:|:------:|
| L_q + L_r | 10+10→11bit 加法器 | 8 | ~10 LUT | ~80 |
| 饱和逻辑 | MUX + 比较 | 8 | ~5 LUT | ~40 |
| **小计** | | | | **~120 LUT** |

### 3.5 符号处理

| 操作 | 说明 | LUT |
|:----|:----|:---:|
| sign(L_q) 提取 | MSB 直接取 | 0 |
| prod_sign (XOR tree) | 8-bit XOR → 3级 | ~15 |
| L_r 符号赋值 | MUX | ~20 |
| **小计** | | **~35 LUT** |

### 3.6 控制逻辑

| 单元 | 说明 | LUT |
|:----|:----|:---:|
| 行列计数器 | 行/迭代计数 | ~30 |
| 地址生成器 | P 矩阵展开 + 存储地址 | ~100 |
| 早停检测 | syndrome 累加 + 比较 | ~50 |
| 状态机 | idle/run/done | ~30 |
| 流水线寄存器 | 各级流水 | ~100 |
| **小计** | | **~310 LUT** |

### 3.7 LUT 汇总

| 模块 | LUT 估算 |
|:----|:-------:|
| min1/min2 比较器 | 130 |
| α 缩放 | 90 |
| VN 更新 (加法+饱和) | 120 |
| 符号处理 | 35 |
| 控制逻辑 | 310 |
| **合计 (纯 LUT)** | **~685 LUT** |
| 加 30% 余量 (布线/接口) | **~900 LUT** |

> 对于 Xilinx 7-series XC7K70T (41,000 LUT): 占用 **< 3%**

### 3.8 DSP 使用

| 方案 | DSP 使用 | 说明 |
|:----|:-------:|:----|
| 纯 LUT (默认) | **0** | α 缩放用移位加法，无需乘法器 |
| 用 DSP 优化 | **8** | 将 α 缩放放入 DSP48，节省 LUT |

## 4. 吞吐率分析

### 4.1 时序估算

| 阶段 | 周期数 | 说明 |
|:----|:-----:|:----|
| 初始化 | 2~3 | 加载 LLR 输入，清零内部状态 |
| 每行处理 | 1 | 所有 8 个 VN 并行处理 |
| 每迭代 | 324 | M=324 行 |
| 早停检查 | 1 | syndrome 全零检测 (可流水) |
| 输出 | 1 | 读取硬判决结果 |

### 4.2 吞吐率计算

| 参数 | 值 |
|:----|:--:|
| 时钟频率 | **200 MHz** (典型 FPGA) |
| 周期时间 | 5 ns |
| 循环/迭代 | 324 (逐行) 或 12 (逐块行) |
| 平均迭代次数 | **4** (SNR=2.5dB) |
| 最大迭代次数 | 10~20 |

**逐行串行 (1 expanded row/cycle)**:

| 迭代 | 周期 | 延迟 | 吞吐率 (info) |
|:---:|:----:|:----:|:------------:|
| 1 | 324 | 1.62 μs | 200 Mbps |
| 4 | 1,296 | 6.48 μs | **50 Mbps** |
| 10 | 3,240 | 16.2 μs | 20 Mbps |

**ZC 块行并行 (27 expanded rows/cycle)**:

利用 QC-LDPC 结构，同时处理一个 block row 的所有 Z=27 个 expanded rows。

| 迭代 | 周期 | 延迟 | 吞吐率 (info) |
|:---:|:----:|:----:|:------------:|
| 1 | 12 | 60 ns | 5.4 Gbps |
| 4 | 48 | 240 ns | **1.35 Gbps** |
| 10 | 120 | 600 ns | 540 Mbps |

### 4.3 硬件成本-吞吐率权衡

| 架构 | LUT | BRAM | 吞吐率 @4iter | 适用场景 |
|:----|:---:|:----:|:------------:|:-------|
| 逐行串行 | ~900 | 2 | 50 Mbps | 低功耗、低成本 |
| 2× 行并行 | ~1,600 | 2 | 100 Mbps | 均衡 |
| 块行并行 (×27) | ~20,000 | 27 | **1.35 Gbps** | 高性能 802.11n |

### 5.3 与其他模块对比

假设 OFDM 系统包含以下模块：

| 模块 | LUT | BRAM | DSP |
|:----|:---:|:----:|:---:|
| **LDPC 译码器** | **~900** | **2** | **0** |

| 信道估计 | ~2,000 | 6 | 8 |
| QAM 解映射 | ~500 | 1 | 0 |
| 解交织 | ~300 | 2 | 0 |

LDPC 译码器仅占整个基带处理的一小部分。

## 6. 总结

| 指标 | 推荐值 |
|:----|:-----:|
| LUT | **~900** (XC7K70T: 2.2%) |
| BRAM | **2 个** 36Kb (1.5%) |
| DSP | **0** (纯 LUT) |
| 最大频率 | **200 MHz** |
| 延迟 (4 iter) | **6.5 μs** |
| 吞吐率 (4 iter) | **50 Mbps** (info) |
| 功耗估计 | **< 0.5 W** (典型) |

**优势**:
- QC-LDPC 结构天然支持高效块级处理
- P 矩阵极小 (1440 bit)，无需外部 H 存储
- 无乘法器需求（α ×0.75 = 移位+加法）
- 2 BRAM 即可容纳全部状态
