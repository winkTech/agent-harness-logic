## ❌ 修正的失误

### 1. 写完代码没 lint（最该罚的）

**经过**: 改完 h_matrix_addr.v 后直接提交，没运行 `iverilog` 检查。等写了几个文件后才发现语法错误。

**根因**: 规范里把 lint 写在"工具使用"章节（参考资料），不是"工作流强制步骤"。**规范本身有漏洞，我也没自觉执行。**

**修正**: 三层补全 —— CLAUDE.md §5.1（全局铁律）+ SKILL.md §20.1（Skill 级强制）+ review.md §0（审查门禁）。写完不 lint 的代码不得提交。

**告诫**: **规范说"可以"≠必须执行。规范说"必须"才需要执行。如果规范没写"必须"，补上它而不是绕过它。**

### 2. reference-index.md 残缺

**经过**: CLAUDE.md 砍掉 10 个文件指针章节，合并成一句"详见 reference-index.md"。但 index 本身只有 2 项，10 个条目全部缺失 → 被砍的章节在实际使用中无法被找到。

**根因**: **改A（CLAUDE.md）时忘了改B（reference-index.md）。** 拆解动作时只看到了自己的目标（精简 CLAUDE.md），没检查下游依赖。

**修正**: 补全 10 个条目，同时验证所有指针的双向一致性。

**告诫**: **重构引用关系时，必须验证"声称的内容"和"实际可寻址的内容"一致。** 不只是文件存在，内容也要匹配。

### 3. CLAUDE.md 优化后行数写错

**经过**: 版本记录写 "~60 行"，实际 41 行。虽是小错误，说明提交前没做最终核对。

**告诫**: **提交前的最后一步应该快速验证关键数字（行数/token 量/文件数）。**

## ⚠️ 告诫未来的自己

### 1. 写完代码第一件事：lint

```
写代码 → 保存 → iverilog/g2012 → 0 error? → 提交
                   ↓ error > 0
              改到 0 error 再提交
```

不管多信任自己的代码，运行一下 `iverilog` 只需要 0.5 秒。**这 0.5 秒不可省略。**

### 2. 改A必查B

任何重构/精简/合并操作，**影响的不仅是当前文件**。列出所有"声称涉及当前文件"的下游，逐一检查。

这次 CLAUDE.md 说"详见 reference-index.md" → 检查 reference-index.md
下次 CLAUDE.md 说"参考 skills-catalog.md" → 检查 skills-catalog.md

**公式**: 改指针 → 查被指文件。改被指文件 → 查所有指过来的文件。

### 3. 规范是活的

规范没写的 → 补上。规范写了但不够明确的 → 明确化。规范写了但没执行的 → 追问为什么。

不要接受"规范里提到过"——要确认是"参考资料"还是"强制规则"。两者的区别决定了 agent 是否必须执行。

### 4. LDPC 审查的示范价值

这次审查发现的 3 个 Bug 代表了 **RTL 中最容易忽视的 3 类问题**：
- **不可综合语法**：只仿真没综合过 → 查所有非 2^n 的除法
- **时序竞争**：同一信号既清零又置位 → 查所有 if-else 优先级
- **数据量不匹配**：输出 1 拍但数据有 N 个 → 查状态机覆盖

每次写 RTL 前对照 [RTL 可靠性 Checklist](learnings/2026-06-03-ldpc-rtl-review-lessons.md) 的 14 条。
