## 1. NTN 概述

### 1.1 3GPP NTN 标准化历程

NTN (Non-Terrestrial Networks) 是 3GPP 将 5G NR 扩展到卫星平台的标准框架, 旨在利用卫星、无人机等非地面平台实现全球覆盖。

| 版本 | 阶段 | 年份 | 核心内容 |
|:----|:----|:----|:----|
| **R15** | SI (研究项目) | 2018 | TR 38.811 NTN 场景定义: 信道模型、部署场景、系统参数 |
| **R16** | WI (工作项目) — IoT NTN | 2020 | TR 38.821 NTN 解决方案研究; NB-IoT/eMTC 卫星接入标准化 |
| **R17** | WI — NR NTN | 2022.06 | TS 38.300 §14 NTN 架构; 大时延/多普勒补偿; 透明转发 baseline; 2-step RACH 增强 |
| **R18** | WI — NR NTN 增强 | 2024.03 | 再生转发 (regenerative payload); 星间链路 (ISL); 增强移动性; RedCap NTN; IoT NTN 增强 |

核心规范引用:

| 规范 | 标题 | NTN 相关内容 |
|:----|:----|:----|
| **TR 38.811** | Study on NR to support NTN | 场景定义、信道模型 (GEO/MEO/LEO/HAPS)、多普勒/延迟参数 |
| **TR 38.821** | Solutions for NR to support NTN | NTN 架构选项、时序/同步方案、HARQ 增强、移动性管理 |
| **TS 38.300 §14** | NR 总体描述 — NTN 架构 | NTN 网络架构、透明/再生转发、馈线链路 |
| **TS 38.101-5** | NR UE RF — NTN | NTN UE 射频要求 (发射/接收、EIRP、频率误差) |
| **TS 38.133 §12** | NR RRM — NTN | NTN 无线资源管理要求 (定时、频率、移动性) |

### 1.4 NTN 在 5G 架构中的定位

NTN 根据 gNB 功能在星地之间的分布分为三种架构模式:

#### 模式 1: 透明转发 (Bent-pipe / Transparent Payload)

```
         ┌────────────────────────────────────────────────────┐
         │                     卫星 (透明转发器)                │
         │    ┌───────────┐          ┌───────────┐            │
         │    │  RF 变频   │   ...    │  功放/放大  │            │
         │    │  (Feeder↔Service Link)  │            │            │
         │    └───────────┘          └───────────┘            │
         └──────────┬─────────────────────┬───────────────────┘
                    │ Feeder Link         │ Service Link
                    │ (馈线链路, 1跳)       │ (服务链路, 1跳)
              ┌─────┴─────┐          ┌─────┴─────┐
              │  NTN gNB   │          │  NTN UE   │
              │  (地面)    │          │           │
              │ ┌────────┐ │          └───────────┘
              │ │CU + DU │ │
              │ │+ LowPHY│ │
              │ └────────┘ │
              └─────┬───────┘
                    │ NG-C / NG-U
              ┌─────┴─────┐
              │    5GC    │
              └───────────┘
```

**透明转发特征**:

| 特性 | 说明 |
|:----|:----|
| 卫星角色 | 仅 RF 变频和功率放大, 无基带处理 |
| gNB 位置 | 完全在地面 (通过馈线链路连接卫星) |
| 处理延迟 | 馈线链路 + 服务链路各一跳, 总 RTT 含双跳 |
| 优点 | 卫星载荷简单、功耗低、可利旧现有卫星平台 |
| 缺点 | 需要地面关口站覆盖, 总延迟较高 |
| 标准化 | R17 NR NTN baseline 方案 |

#### 模式 2: 再生转发 (Regenerative Payload)

```
         ┌────────────────────────────────────────────────────┐
         │              卫星 (再生载荷, 含部分 gNB)              │
         │    ┌────────────┐    ┌────────────────────┐        │
         │    │   RF 前端   │    │  gNB-DU (部分功能)  │        │
         │    │  + Low-PHY  │    │  或 gNB-CU         │        │
         │    └────────────┘    └──────────┬─────────┘        │
         │                                  │ ISL (星间链路)    │
         │                                  │ 可选              │
         └──────────┬───────────────────────┼──────────────────┘
                    │ Service Link          │
              ┌─────┴─────┐           ┌─────┴─────┐
              │  NTN UE   │           │  相邻卫星  │
              └───────────┘           └───────────┘
                    ▲
                    │ Feeder Link (或 ISL 到地面关口站)
              ┌─────┴─────┐
              │  NTN GW   │
              │  + 5GC    │
              └───────────┘
```

| 特性 | 说明 |
|:----|:----|
| 卫星角色 | 承担部分或全部 gNB 基带处理功能 |
| gNB 位置 | DU 或 CU 在星上, 地面仅网关/5GC |
| 星间链路 (ISL) | 可选, 卫星间通过激光/毫米波互联, 减少关口站数量 |
| 优点 | 减少馈线链路延迟, 独立于地面网络的覆盖能力 |
| 缺点 | 卫星功耗/热管理复杂, 载荷设计难度高 |
| 标准化 | R18 引入 (R17 仅基础研究) |

#### 模式 3: 星载 gNB (Full On-Board gNB)

| 特性 | 说明 |
|:----|:----|
| gNB 位置 | CU + DU 全部部署在卫星上 |
| 地面依赖 | 仅需 5GC 通过馈线链路或 ISL 连接 |
| 路由方式 | 星间链路 (ISL) 为核心的星上路由网络 |
| 标准化阶段 | 长期演进目标 (3GPP 尚未完整标准化) |

#### 处理链对比

```
透明转发 (Bent-pipe):
  上行: UE ──Service Link──▶ 卫星(RF变频) ──Feeder Link──▶ gNB(地面) ──▶ 5GC
  下行: 5GC ──▶ gNB(地面) ──Feeder Link──▶ 卫星(RF变频) ──Service Link──▶ UE
  总RTT = 2×(Service延迟 + Feeder延迟) + gNB处理

再生转发 (Regenerative):
  上行: UE ──Service Link──▶ 卫星(gNB-DU) ──ISL/Feeder──▶ 地面网关 ──▶ 5GC
  下行: 5GC ──▶ 地面网关 ──ISL/Feeder──▶ 卫星(gNB-DU) ──Service Link──▶ UE
  总RTT = 2×Service延迟 + Feeder延迟 + 星上处理
```

## 2. NTN 信道特性

### 2.1 大传播延迟

NTN 最显著的特征是远大于地面蜂窝的传播延迟。延迟主要由轨道高度决定。

| 场景 | 轨道高度 | 最小单程延迟 (90度仰角) | 最大单程延迟 (最小仰角) | 往返延迟 (RTT, 含馈线) |
|:----|:----|:----|:----|:----|
| **GEO** | 35,786 km | 119.3 ms | 139.3 ms (10度仰角) | ~480–560 ms (双跳) |
| **MEO (O3b)** | 8,062 km | 26.9 ms | ~40 ms | ~108–160 ms |
| **LEO (Starlink 550km)** | 550 km | 1.83 ms | ~7.5 ms (25度) | ~12–30 ms (双跳) |
| **LEO (OneWeb 1200km)** | 1,200 km | 4.0 ms | ~12 ms (25度) | ~20–50 ms (双跳) |
| **地面蜂窝** | 0.03–0.1 km | <0.001 ms | 0.03 ms (10km) | <0.1 ms |

**GEO 延迟详细分解** (透明转发):

```
RTT 分解 (GEO, 30度仰角, 透明转发):
  ┌────────────────────────────────────────────────────┐
  │  服务链路 下行 (卫星→UE):    ~123 ms                │
  │  服务链路 上行 (UE→卫星):    ~123 ms                │
  │  馈线链路 上行 (gNB→卫星):   ~123 ms                │
  │  馈线链路 下行 (卫星→gNB):   ~123 ms                │
  │  gNB 内部处理:               ~10–30 ms             │
  │  UE 内部处理:                ~5–10 ms              │
  ├────────────────────────────────────────────────────┤
  │  总计 RTT:                   ~507–532 ms           │
  └────────────────────────────────────────────────────┘
```

### 2.2 大多普勒频移

LEO 卫星高速运动产生显著的多普勒频移。多普勒频移量与载波频率和相对速度成正比。

$$f_d = \frac{v}{c} \cdot f_c \cdot \cos\theta$$

其中 $v$ 为卫星相对速度, $c$ 为光速, $f_c$ 为载波频率, $\theta$ 为信号方向与卫星速度矢量的夹角。

| 场景 | 轨道高度 | 卫星速度 | 最大多普勒 (C-band 4GHz) | 最大多普勒 (Ka 20GHz) | 多普勒变化率 |
|:----|:----|:----|:----|:----|:----|
| **GEO** | 35,786 km | ~0 (相对静止) | < 0.01 ppm | < 0.01 ppm | ~0 Hz/s |
| **LEO (550 km)** | 550 km | ~7.6 km/s | ±48 ppm (±192 kHz) | ±48 ppm (±960 kHz) | ~800 Hz/s |
| **LEO (1200 km)** | 1,200 km | ~7.3 km/s | ±40 ppm (±160 kHz) | ±40 ppm (±800 kHz) | ~400 Hz/s |
| **HAPS** | 20 km | 静态/低速 | < 0.1 ppm | < 0.1 ppm | ~0 Hz/s |
| **地面蜂窝** | N/A | <500 km/h (高铁) | ±0.5 ppm | ±0.5 ppm | <20 Hz/s |

**LEO 多普勒时间演变** (典型过顶场景):

```
多普勒频移
    +48ppm ●                    (卫星从地平线升起)
    +40ppm │＼
    +30ppm │  ＼
    +20ppm │    ＼
    +10ppm │      ＼
       0   │────────●────────── (天顶, 零多普勒)
    -10ppm │          ＼
    -20ppm │            ＼
    -30ppm │              ＼
    -40ppm │                ＼
    -48ppm │                  ●  (卫星落向地平线)
          └──────────────────────→ 时间
           │←── 可见窗口 (5-15分钟) ──→│

多普勒变化率: 最高在近地平 (~800 Hz/s), 在天顶附近接近零
```

### 2.3 路径损耗

NTN 路径损耗在自由空间损耗 (FSPL) 基础上还需考虑大气衰减、降雨衰减和闪烁效应。

| 损耗来源 | 量级 (典型) | 频率相关性 | 说明 |
|:----|:----|:----|:----|
| **自由空间损耗 (FSPL)** | GEO: ~190 dB (4GHz) / ~208 dB (28GHz) | $20\log_{10}(f) + 20\log_{10}(d)$ | 主要损耗源 |
| **大气吸收** | 0.1–1.0 dB (天顶) | 随频率升高, 22/60 GHz 有吸收峰 | 氧气/水蒸气谐振吸收 |
| **降雨衰减** | 2–15 dB (Ka 波段, 99.9% 可用度) | 强频率相关 (>10 GHz) | 热带地区可达 20+ dB |
| **云/雾衰减** | 0.5–3 dB | 随频率升高 | 与液态水含量相关 |
| **电离层闪烁** | 1–10 dB (赤道/极地区域) | 低频 (<2 GHz) 更严重 | 太阳活动影响 |
| **建筑物/植被遮挡** | 10–30 dB | 全频段 | 非视距 (NLOS) 场景 |
| **极化失配** | 0.5–3 dB | 低相关性 | 圆极化→线极化或法拉第旋转 |

**NTN vs 地面蜂窝路径损耗对比**:

| 参数 | 地面蜂窝 (FR1 宏站) | NTN LEO (550km, S-band) | NTN GEO (C-band) |
|:----|:----|:----|:----|
| 距离 | 0.1–10 km | 550–1,800 km | 35,786–41,000 km |
| FSPL | 80–130 dB | 152–175 dB | 190–196 dB |
| 额外损耗 | — | 5–15 dB (大气/雨水/闪烁) | 8–20 dB |
| 总路径损耗 | 80–150 dB | 160–190 dB | 200–215 dB |
| UE EIRP 需求 | +23 dBm (Power Class 3) | +26–+39 dBm (NTN UE) | +39–+50 dBm (VSAT 终端) |

## 3. NR NTN 帧结构调整

### 3.1 时序提前 (TA) 预补偿

地面 NR 中, TA 用于补偿 UE 与 gNB 之间的传播延迟。NTN 中延迟远大于地面, 且随时间变化 (LEO 卫星运动), 传统闭环 TA 机制无法满足需求。

**NTN TA 预补偿原理**:

```
TA 总提前 = TA_common + TA_UE

  TA_common: gNB 广播, 补偿服务链路的公共延迟分量
             (基于卫星星历和参考点计算)

  TA_UE:     UE 自主计算, 补偿服务链路的差分延迟
             (基于星历 + UE GNSS 位置)
```

| 参数 | 来源 | 计算方式 | 粒度 |
|:----|:----|:----|:----|
| **TA_common** | gNB 通过 SIB 广播 | 卫星到参考点 (小区中心) 的传播延迟 | $T_c$ ($\approx$ 0.509 ns) |
| **TA_UE** | UE 本地计算 | $\text{TA\_UE} = (d_{\text{UE-sat}} - d_{\text{ref-sat}}) / c$ | $T_c$ |
| **星历数据** | gNB 通过 SIB 广播 | 开普勒参数 或 位置+速度矢量 | — |
| **UE 位置** | UE GNSS 接收机 | GPS/北斗/Galileo (NTN UE 强制 GNSS) | 米级 |
| **馈线链路 TA** | gNB 内部处理 | 透明转发时, gNB 额外补偿馈线链路延迟 | 系统内部 |

**TA 预补偿时序图**:

```
                       参考点 (小区中心)
UE 位置                      │
  │                          │
  │  ← d_UE-sat →            │ ← d_ref-sat →
  │                          │
  └──────────────────────────┼────────────────────
                             │
                       ┌─────┴─────┐
                       │   卫星     │
                       └───────────┘
                             │
                      ┌──────┴──────┐
                      │   gNB (地面) │
                      └─────────────┘

TA_common = 2 × d_ref-sat / c  (gNB 广播)
TA_UE     = 2 × (d_UE-sat - d_ref-sat) / c  (UE 计算)
总 TA     = TA_common + TA_UE
```

**TA 精度要求**: UE 位置精度 50m → TA 误差 ~0.33 μs, 落在 NR CP 范围内 (Normal CP ~5.2 μs, Extended CP ~16.7 μs)。

### 3.2 K_offset: 调度时延偏移

地面 NR 中 PDCCH→PDSCH/PUSCH 的调度时延 (K0/K2) 较小 (0–32 时隙)。NTN 中服务链路延迟显著, 需引入 **K_offset** 对调度时序进行扩展。

| 参数 | 地面 NR | NR NTN | 说明 |
|:----|:----|:----|:----|
| **K0** (DL grant → PDSCH) | 0 时隙 | 0 + K_offset | PDCCH 和 PDSCH 之间的时隙偏移 |
| **K2** (UL grant → PUSCH) | 1–32 时隙 | K_offset + K2 | PDCCH 和 PUSCH 之间的时隙偏移 |
| **K1** (PDSCH → HARQ-ACK) | 1–8 时隙 | K_offset + K1 | PDSCH 接收和 HARQ-ACK 反馈之间的偏移 |
| **K_offset 取值范围** | N/A | 0 ~ 2^13 – 1 时隙 | R17 定义, 取决于 SCS |
| **K_offset 典型值 (GEO)** | N/A | ~256–1024 (15kHz SCS) | 对应 ~256–1024 ms |
| **K_offset 典型值 (LEO)** | N/A | ~16–128 (15kHz SCS) | 对应 ~16–128 ms |

**K_offset 配置**:

```
PDCCH (DL Grant)
    │
    ├── K_offset 时隙 (等待服务链路传播)
    │
    ▼
PDSCH 实际接收 (UE) 或 PUSCH 发送 (UE)
    │
    ├── K_offset 时隙 (等待服务链路传播 + UE 处理)
    │
    ▼
HARQ-ACK / UL Grant 到达 gNB
```

K_offset 值由 gNB 通过 RRC (`K-offset-r17`) 或 DCI (部分) 配置给 UE, 与小区级的 `ntn-Config` IE 关联。

### 3.3 RTT (往返时间) 与 UE 初始获取

UE 需要在初始接入前获取服务链路 RTT, 用于计算初始 TA 和 PRACH 发送定时。

| 步骤 | 内容 | 方式 |
|:----|:----|:----|
| 1 | UE 获取自身位置 | GNSS (GPS/北斗) |
| 2 | UE 获取卫星星历 | 从 SIB19 (NR NTN) 读取星历信息 |
| 3 | UE 计算卫星位置 | 基于星历+当前时间外推 |
| 4 | UE 计算 UE-卫星距离 | $\|\vec{r}_{\text{sat}} - \vec{r}_{\text{UE}}\|$ |
| 5 | UE 计算 RTT | $\text{RTT} = 2 \times d_{\text{UE-sat}} / c$ (不含馈线) |
| 6 | UE 计算 TA 预补偿 | 基于 RTT 和服务链路 TA |

**NTN-Config RRC IE 关键字段**:

| 字段 | 含义 | 说明 |
|:----|:----|:----|
| `cellSpecificKoffset-r17` | 小区级 K_offset | 基本时延偏移, 所有 UE 共用 |
| `ta-Info-r17` | TA 信息 | `ta-Common`, `ta-CommonDrift`, `ta-CommonDriftVariant` |
| `ephemerisInfo-r17` | 星历信息 | 轨道参数 (位置/速度 或 开普勒参数) |
| `epochTime-r17` | 星历参考历元 | 星历参数的参考时间点 |
| `ntn-PolarizationDL-r17` | DL 极化方式 | LHCP / RHCP (圆极化) |
| `ntn-PolarizationUL-r17` | UL 极化方式 | LHCP / RHCP |

### 3.4 SFN 与时间漂移

LEO 卫星的运动导致 UE 感知到的帧定时不断漂移。

```
时间漂移示意 (LEO, 550km, 可见窗口 ~10分钟):

SFN 定时误差 (不含 TA):
  刚升起:      参考 SFN 超前 ~1.8 ms → 需 SFN 偏移
  过顶 (天顶):  参考 SFN 超前 ~1.8 ms (最短距离)
  降落前:       参考 SFN 超前 ~7.5 ms (最远距离)
  
时间漂移率: 最大 ~0.1 ppm (取决于轨道和仰角)
```

| 处理机制 | 说明 |
|:----|:----|
| **TA_common 更新** | gNB 周期性广播更新 TA_common (如每 10s), 适配卫星运动 |
| **TA_drift** | UE 基于星历和自身运动计算 TA 随时间的一阶/二阶变化率, 持续修正 |
| **SFN 偏移指示** | gNB 通过 SIB 指示当前 SFN 偏移量, 使 UE RRC 连接期间帧号对齐 |
| **UE 自主补偿** | UE 根据预补偿 TA 提前发送, gNB 侧所有 UE 信号在共同参考时基上对齐 |

## 4. PRACH 与初始接入

### 4.1 NTN PRACH 面临的挑战

NTN PRACH 在地面 NR PRACH 基础上需额外应对三个核心问题:

| 挑战 | 地面 NR | NR NTN | 影响 |
|:----|:----|:----|:----|
| **大往返延迟** | <1 ms | 5–270 ms (LEO/GEO) | 前导检测时间窗口大, RAR 等待时间长 |
| **大多普勒频移** | < 0.5 ppm | ±48 ppm (LEO) | 相关峰偏移, 检测门限升高 |
| **大差分延迟** | < 30 μs | 0.4–8 ms (LEO/GEO) | 不同 UE 前导到达时刻分散, 小区内干扰 |

### 4.2 PRACH 格式选择

NTN 场景优先选用长前导和高重复因子格式, 以提供足够的处理增益来补偿大路径损耗。

| 前导格式 | 序列长度 | $T_{SEQ}$ (典型 SCS) | 总长度 (ms) | 处理增益 | NTN 适用性 |
|:----|:----|:----|:----|:----|:----|
| **Format 0** | 839 | 800 μs (1.25 kHz) | 1.0 | 基准 (+29.2 dB) | LEO 基本覆盖 |
| **Format 1** | 839 | 800 μs (1.25 kHz) | 2.0 | 基准 + 3 dB (长 CP) | LEO/MEO 远覆盖 |
| **Format 2** | 839 | 1,600 μs (1.25 kHz) | 2.0 | 基准 + 3 dB (长 SEQ) | LEO/MEO/GEO |
| **Format 3** | 839 | 1,600 μs (1.25 kHz) | 3.0 | 基准 + 4.8 dB | GEO 超远覆盖 |
| **B4** (短) | 139 | 56.25 μs (30 kHz) × 12 重复 | ~0.64 | 短序列 -7.8 + 重复 +10.8 = +3 dB | LEO 可选 |
| **C2** (短) | 139 | 18.75 μs (30 kHz) × 2 + 重复 | ~0.25 | 短序列 -7.8 + 重复 +3 = -4.8 dB | LEO 低延迟 |

**推荐**: GEO 优先使用 Format 2/3, LEO 使用 Format 0/1/2, 短格式仅在高 SNR 场景可用。

### 4.3 TA 预补偿流程

NTN PRACH 的关键创新: UE 在发送 PRACH 前已经完成 TA 预补偿, 而非依赖 gNB 测量后下发。

```
NTN PRACH 初始接入流程 (UE 侧):

  Step 1:  GNSS 定位 → 获取自身纬度/经度/高度
  Step 2:  读取 SIB19 → 获取卫星星历 (轨道参数)
  Step 3:  计算卫星当前位置 → 基于星历 + 当前 UTC 时间
  Step 4:  计算 UE-卫星距离 = |r_sat - r_UE|
  Step 5:  计算 TA_common (广播值) + TA_UE (差分)
  Step 6:  计算 PRACH 发送定时: T_tx = T_rx_SSB - TA_total
  Step 7:  以预补偿后的定时发送 PRACH
```

| TA 分量 | 计算方式 | 使用场景 |
|:----|:----|:----|
| **TA_common** (小区公共部分) | gNB 广播, 服务链路参考点到卫星的 RTT | 所有 UE 共用 |
| **TA_UE** (UE 专用部分) | UE 基于位置/星历计算差分 TA | CBRA 和 CFRA 均需 |
| **馈线链路 TA** | gNB 内部管理 | 仅 gNB 侧处理, UE 不感知 |

### 4.4 2-step RACH (Type-2) 在 NTN 中的应用

R17 NR NTN 支持 2-step RACH, 显著减少接入时延。

| 对比维度 | 4-step RACH (Type-1) | 2-step RACH (Type-2) |
|:----|:----|:----|
| 消息交互次数 | 4 (Msg1→Msg2→Msg3→Msg4) | 2 (MsgA→MsgB) |
| LEO 接入时延 (含传播) | ~50–100 ms | ~30–60 ms |
| GEO 接入时延 (含传播) | ~1,100–1,200 ms | ~600–700 ms |
| UE 实现复杂度 | 低 | 中 (MsgA 联合发送前导+PUSCH) |
| 覆盖要求 | 中等 | 高 (MsgA PUSCH 需可靠解码) |
| NTN 适用场景 | 全覆盖场景 | LE0 高仰角/强信号场景 |

**NTN 2-step RACH 增强**:

- MsgA 的 PRACH 前导 + PUSCH 在时域通过 TA 预补偿对齐
- MsgB 窗口 (msgB-ResponseWindow) 按 NTN 延迟扩展
- gNB 需同时检测前导并解码 PUSCH, 计算开销高但可减半接入时延

### 4.5 RAR 窗口扩展

地面 NR 的 RAR 窗口 (ra-ResponseWindow) 最大 10 ms, 在 NTN 中远不足够。

| 参数 | 地面 NR (最大) | NR NTN (扩展) | 理由 |
|:----|:----|:----|:----|
| **ra-ResponseWindow** | 1–10 时隙 | 1–**40/80 ms** | 补偿长传播延迟 |
| **msgB-ResponseWindow** (2-step) | 1–32 时隙 | 1–**80/160 ms** | 2-step RACH MsgB 窗口 |
| **ra-ContentionResolutionTimer** | 8–64 子帧 | **扩展到秒级** | GEO 场景竞争解决等待 |

```
RAR 时间线 (GEO, 透明转发):

UE 发送 Msg1  (TA 预补偿)
  │
  ├── 服务链路延迟上行 (~120 ms)
  │
  ▼
卫星 → gNB (馈线链路 ~120 ms)
  │
  ├── gNB 处理 (PRACH 检测 + RAR 生成, ~5–20 ms)
  │
  ▼
gNB → 卫星 (馈线链路 ~120 ms)
  │
  ├── 服务链路延迟下行 (~120 ms)
  │
  ▼
UE 接收 Msg2 (RAR)

总等待时间: ~485–500 ms → RAR 窗口需 ≥ 500 ms
```

### 4.6 大多普勒下的 PRACH 检测

LEO 卫星大多普勒频移对 ZC 序列检测产生显著影响。

**多普勒对 ZC 序列的影响**:

$$x_u(n) \xrightarrow{f_d} x_{u}(n) \cdot e^{j2\pi f_d n T_s}$$

频域表现: ZC 序列的频率偏移 $\Delta f$ 导致 PDP 上出现额外的相关峰, 偏移量:

$$\Delta_{peak} = \pm (u^{-1} \bmod L_{RA}) \cdot \Delta f \cdot T_{SEQ}$$

| 多普勒效应 | 影响 | 应对措施 |
|:----|:----|:----|
| 主峰偏移 | PDP 峰值位置漂移 | Ncs 增大, 增强搜索窗 |
| 模糊峰产生 | 频率偏移 > 1/T_SEQ 时出现假峰 | 受限集 (Restricted Set) 或双窗口检测 |
| 检测 SNR 恶化 | 多普勒破坏 ZC 序列的正交性 | 多普勒预补偿 (UE 侧基于星历预校正发射频率) |

**UE 侧多普勒预补偿**:

$$f_{TX} = f_{DL} - f_{d,DL} - f_{d,UL}$$

其中 $f_{d,DL}$ 和 $f_{d,UL}$ 为 UE 基于星历+自身位置计算的上下行多普勒频移, 在线性频域进行预校正后, gNB 侧看到接近零频偏的信号。

## 5. HARQ 与调度

### 5.1 HARQ 停等问题

地面 NR HARQ 依赖快速的 ACK/NACK 反馈循环 (RTT 定时器 ~2–16 ms)。NTN 中大传播延迟导致 HARQ RTT 远大于标准定时器范围。

| 场景 | 近似 RTT | HARQ RTT 定时器 (TS 38.331) | 能否匹配 | 问题 |
|:----|:----|:----|:----|:----|
| 地面 NR | <2 ms | 2–16 ms (可配) | 匹配 | — |
| LEO (550 km, 透明) | 12–30 ms | 最大 ~32 ms (扩展) | 边界 | 需扩展 HARQ 定时器 |
| LEO (1200 km, 透明) | 20–50 ms | 同上 | 不匹配 | 需禁用或大幅扩展 |
| GEO (透明) | 480–560 ms | 同上 | 不匹配 | 必须禁用 HARQ 反馈 |

### 5.2 R17 HARQ 解决方案

R17 NR NTN 定义了两种 HARQ 处理方式:

#### 方案 A: 禁用 HARQ-ACK 反馈 (HARQ Feedback Disabled)

| 特性 | 说明 |
|:----|:----|
| 原理 | gNB 通过 RRC 配置 `harq-FeedbackDisabled-r17`, UE 不发送 HARQ-ACK |
| K1 值 | 设为 "inapplicable" (不确定), DCI 中 K1 字段被重新解释 |
| 可靠性保障 | 依赖 **RLC AM 模式 ARQ 重传** 替代 HARQ |
| 适用场景 | GEO 全覆盖, 或 LEO 中高延迟场景 |
| 缺点 | 无 PHY 层快速重传, 丢包恢复延迟较大 |

**RLC ARQ 机制替代 HARQ**:

```
PHY:  发送 TB  →  无 HARQ-ACK 反馈  →  不触发 HARQ 重传
RLC:  轮询 (Poll) 请求状态报告 (STATUS PDU)
      → RLC 状态报告指示缺失的 RLC SDU
      → RLC 层重传
      → 恢复延迟 = RLC 轮询间隔 + RTT + 重传时间
```

#### 方案 B: 扩展 HARQ 定时器 (适用于 LEO)

| 特性 | 说明 |
|:----|:----|
| 原理 | K1 值扩展至大于 RTT, 允许 HARQ-ACK 正常反馈 |
| K1 最大值扩展 | 从 8 时隙扩展到 `K1 + K_offset` (最大 2^13 – 1 时隙) |
| HARQ 进程数 | 需增加至 32 或更多 (R17: `nrofHARQ-ProcessesForPDSCH-r17` 可配) |
| 适用场景 | LEO 低延迟场景 (RTT < HARQ 定时器最大值) |

### 5.3 K_offset 与调度时序扩展

| 参数 | 地面 NR 范围 | NTN 扩展范围 | 计算公式 |
|:----|:----|:----|:----|
| **K0** (DL) | 0–32 时隙 | 0 ~ K_offset_max | $K0_{NTN} = K0 + K\_offset$ |
| **K1** (DL ACK) | 1–8 时隙 | 1 ~ K_offset_max | $K1_{NTN} = K1 + K\_offset$ (或 RRC 单独配置) |
| **K2** (UL) | 1–32 时隙 | K_offset + 1 ~ K_offset + 32 | $K2_{NTN} = K2 + K\_offset$ |
| **K_offset 最大值** | N/A | 0 ~ 8191 时隙 | 取决于 SCS |
| **K_offset (15kHz SCS)** | N/A | 最大 8,191 ms (~8.2 s) | GEO 适用 |
| **K_offset (120kHz SCS)** | N/A | 最大 ~68.3 s | 超出任何实用需求 |

### 5.4 PUSCH 调度增强

NTN 中 PUSCH 调度需额外考虑:

| 增强项 | 说明 |
|:----|:----|
| **多 UL Grant 同时激活** | UE 可同时持有多个 UL grant (对应不同 HARQ 进程), 应对大 RTT 下调度效率问题 |
| **CG (Configured Grant) 增强** | CG 周期 + CG 定时器按 NTN 扩展; 支持 CG-SDT (小数据传输) |
| **K2 扩展** | PUSCH 调度时延从 32 时隙扩展到 K_offset + 32 |
| **UL 时间对齐** | `timeAlignmentTimer` (TAT) 扩展, 适应 TA 的缓慢变化 |

## 6. 移动性管理

### 6.1 LEO 卫星移动特性

LEO 卫星高速运动导致 UE 经历频繁的服务卫星/波束切换。

| 参数 | Starlink (550 km) | OneWeb (1200 km) |
|:----|:----|:----|
| 轨道周期 | ~95.5 min | ~109 min |
| 过顶时长 (单次可见) | ~5–8 min | ~8–15 min |
| 星下点速度 | ~7.6 km/s | ~7.3 km/s |
| 波束驻留时间 (地面固定点) | ~10–60 s (取决于波束大小) | ~30–120 s |
| 卫星过顶切换频率 | 每 5–15 min (取决于纬度) | 每 10–20 min |
| 波束间切换频率 | 每 10–60 s | 每 30–120 s |
| 馈线链路切换频率 | 每 3–8 min (取决于关口站数量) | 每 5–15 min |

### 6.2 NTN 切换类型

```
NTN 切换类型:

  1. 卫星内波束切换 (Intra-satellite beam handover)
     UE 在同一卫星的不同波束间切换
     触发: UE 或卫星运动导致波束覆盖边界变化
     频率: 每 10–60 s (LEO)

  2. 卫星间切换 (Inter-satellite handover)
     UE 从一颗卫星切换到另一颗卫星
     触发: 当前卫星即将超出可见范围
     频率: 每 5–15 min (LEO)

  3. 馈线链路切换 (Feeder link switch)
     卫星的馈线链路从关口站 A 切换到关口站 B
     触发: 卫星运动导致原关口站超出覆盖
     频率: 每 3–8 min
     影响: 若 gNB 在地面, 意味着服务 gNB 变更 (gNB 间切换)
```

### 6.3 条件切换 (CHO — Conditional Handover)

R16 引入的条件切换 (CHO) 天然适合 NTN 的可预测切换场景。

| 特性 | 传统切换 (HO) | 条件切换 (CHO) | 在 NTN 中的优势 |
|:----|:----|:----|:----|
| 触发 | gNB 测量报告后即时触发 | UE 在满足预设条件后自主执行 | 避免 HO 命令在卫星链路上的延迟 |
| HO 命令时机 | HO 触发后发送 | 预先发送 (UE 保存) | 减少信令交互, 避免链路中断 |
| 执行条件 | 无需条件 (网络命令) | RRC 配置的事件 (A3/A5 等) | 可预测的卫星运动 + 星历 = 精确触发 |
| 适用性 | 即时反应 | 可预测移动轨迹 | LEO 卫星轨迹高度可预测 |

**NTN CHO 增强**:

- 卫星运动轨迹可预测 → gNB 可提前配置多个目标小区 + 触发条件 (基于时间/星历)
- UE 本地评估 CHO 条件, 无需上行测量报告 (节约信令)
- R18 支持基于星历的 CHO (ephemeris-based CHO), 进一步优化

### 6.4 卫星波束管理

| 波束类型 | 说明 | 优缺点 |
|:----|:----|:----|
| **固定波束 (Earth-fixed)** | 波束长期指向固定地理位置 | UE 服务连续性最好; 卫星需机械或电子扫描补偿运动 |
| **移动波束 (Satellite-fixed)** | 波束随卫星运动在地面扫过 | 卫星实现简单; UE 经历频繁波束切换 |
| **准固定波束 (Quasi-Earth-fixed)** | 波束在一段时间内固定, 然后整体跳变 | 折中方案; 切换可预测 |

```
波束 ID 广播:
  卫星在 SIB 中广播:
    - Beam ID (每波束)
    - 波束中心经纬度 (地球固定坐标)
    - 波束覆盖半径
    - 相邻波束列表 + 对应频率/PCI

UE 使用: 测量 SSB/CSI-RS → 上报波束级别 RSRP → gNB 决定波束切换
```

### 6.5 星历广播

NTN 中星历信息通过 SIB19 广播, 供 UE 计算卫星位置, 用于 TA 预补偿和多普勒预补偿。

**星历格式** (3GPP TS 38.331):

| 星历类型 | 格式 | 参数量 | 精度 | 更新周期 | 适用于 |
|:----|:----|:----|:----|:----|:----|
| **位置 + 速度矢量** | `positionVelocity-r17` | 6 (+ 6 可选) | ~米级 | 10–320 s | LEO/MEO/GEO |
| **开普勒参数** | `orbital-r17` | 7 参数 + 历元时间 (TLE 类) | ~百米级 | 秒级到分级 | LEO/MEO |
| **TLE (Two-Line Element)** | 未直接标准化 (通过开普勒近似) | — | ~公里级 | 小时/天级 | 初始捕获 |

**SIB19 星历内容**:

```
SIB19 (NR NTN) = 星历信息 + 公共 TA 参数
  ├── epochTime-r17          : 星历参考历元 (GPS 时间或 UTC)
  ├── ephemerisInfo-r17      : 位置+速度 或 开普勒参数
  │   ├── positionX-r17      : ECEF X 坐标 (m)
  │   ├── positionY-r17      : ECEF Y 坐标 (m)
  │   ├── positionZ-r17      : ECEF Z 坐标 (m)
  │   ├── velocityVX-r17     : ECEF X 方向速度 (m/s)
  │   ├── velocityVY-r17     : ECEF Y 方向速度 (m/s)
  │   └── velocityVZ-r17     : ECEF Z 方向速度 (m/s)
  └── ta-Info-r17            : TA 参数 (taCommon 等)
```

### 7.2 ITU 无线电规则 (RR) 频率分配

| ITU 区域 | L-band (1–2 GHz) | S-band (2–4 GHz) | C-band (4–8 GHz) | Ku-band (12–18 GHz) | Ka-band (26.5–40 GHz) |
|:----|:----|:----|:----|:----|:----|
| **Region 1** (欧洲/非洲) | MSS 上行 1.6 GHz | MSS 2.0/2.2 GHz | FSS 3.4–4.2 (下行) | FSS 10.7–12.75 (下行) | FSS 17.3–20.2 (下行) |
| **Region 2** (美洲) | 同上 | 同上 | FSS 3.7–4.2 (下行) | FSS 11.7–12.2 (下行) | FSS 17.7–20.2 (下行) |
| **Region 3** (亚洲/大洋洲) | 同上 | 同上 | FSS 3.4–4.2 (下行) | FSS 12.2–12.75 (下行) | FSS 17.7–20.2 (下行) |

**ITU 业务分类**:

| 缩写 | 全称 | 说明 |
|:----|:----|:----|
| **MSS** | Mobile Satellite Service | 卫星移动业务 (终端可移动) |
| **FSS** | Fixed Satellite Service | 卫星固定业务 (关口站/固定终端) |
| **BSS** | Broadcasting Satellite Service | 卫星广播业务 (DTH 直播) |

### 7.3 NTN 功率控制

NTN 功率控制需应对大路径损耗和卫星功率受限。

| 参数 | 地面 NR | NR NTN | 说明 |
|:----|:----|:----|:----|
| UE 最大发射功率 (PC3) | +23 dBm | +26 dBm (NTN UE) | NTN 终端允许更高功率 |
| UE 最大 EIRP | +23 dBm (手机) | +26 ~ +39 dBm | 卫星终端容许更高天线增益 |
| gNB 发射功率 | 40–46 dBm/天线 | 卫星整星功率 ~kW 级, 每波束 ~10–30 W | 卫星功率严重受限 |
| 开环功率控制 | $P_{PRACH} = P_{target} + PL$ | 同上 + 额外偏置 | 需考虑大气/雨水损耗 |
| 闭环功率控制 | TPC 命令 ±1–±3 dB | TPC 响应延迟大 (RTT) | 主要依赖开环 |

### 7.4 最大 EIRP 与 UE 类型

| UE 类型 | 典型天线 | 天线增益 | 最大 EIRP | 典型应用 |
|:----|:----|:----|:----|:----|
| **手持终端 (Handheld)** | 内置贴片天线 | 0–3 dBi | +23 ~ +26 dBm | 手机直连卫星 (Starlink Direct-to-Cell, AST SpaceMobile) |
| **便携终端 (Portable)** | 外置小型天线 | 3–10 dBi | +26 ~ +36 dBm | 平板/笔记本电脑卫星通信 |
| **固定终端 (VSAT/Fixed)** | 定向抛物面/相控阵 | 20–40 dBi | +39 ~ +63 dBm | 家庭/企业宽带, 关口站 |
| **车载/船载 (ESIM)** | 机械/电子扫描天线 | 10–25 dBi | +30 ~ +50 dBm | 车辆、船舶、飞机 |

> 手持终端直连卫星是 NTN 最具挑战的场景: UE EIRP 最低但路径损耗最高, 需低数据速率 (100k–10Mbps) 和强编码。

## 8. NTN 部署模式

### 8.1 部署模式对比

| 模式 | 卫星载荷 | gNB 位置 | 星间链路 (ISL) | 关口站需求 | RTT | 标准成熟度 |
|:----|:----|:----|:----|:----|:----|:----|
| **透明转发 (Bent-pipe)** | RF 变频 + 功放 | 地面 | 无 | 每卫星 1+ 关口站 | 服务链路 ×2 + 馈线×2 | R17 标准化 |
| **再生转发 (Regenerative)** | gNB-DU (部分) | 地上 gNB-CU, 星上 gNB-DU | 可选 | 每多卫星 1 关口站 | 服务链路 ×2 + (ISL 或馈线) | R18 标准化中 |
| **星载 gNB** | Full gNB (CU+DU) | 星上 | 必需 (星上路由) | 仅 5GC 接入点 | 服务链路 ×2 + ISL | 长期 (R19+) |

### 8.2 透明转发 (Bent-pipe) — R17 基线方案

```
                          ┌────────────────┐
                          │     卫星        │
                          │  ┌──────────┐  │
       Service Link       │  │ LNA + HPA│  │     Feeder Link
  ────────────────────────│──│ 变频器    │──│──────────────────────
         (Uu over        │  └──────────┘  │    (卫星专用链路)
          satellite)     └────────────────┘
                                │
                     ┌──────────┴──────────┐
                     │     NTN Gateway      │
                     │  (关口站, 地面站)     │
                     └──────────┬──────────┘
                                │
                     ┌──────────┴──────────┐
                     │   gNB (完整基站)     │
                     │  CU + DU + Low-PHY  │
                     └──────────┬──────────┘
                                │
                     ┌──────────┴──────────┐
                     │        5GC          │
                     └─────────────────────┘
```

| 优势 | 劣势 |
|:----|:----|
| 卫星载荷简单, 技术成熟 | 馈线链路增加额外延迟 (~120 ms × 2) |
| 利旧现有卫星平台 (GEO/Ku 广播卫星) | 关口站部署受限 (需在本国或合作国领土) |
| 地面 gNB 升级和维护便捷 | 星地双跳 RTT 高 |
| 3GPP R17 已完整标准化 | 关口站数量决定覆盖连续性 |

### 8.3 再生转发 (Regenerative) — R18 方向

```
                          ┌──────────────────────────┐
                          │          卫星             │
                          │  ┌──────────────────┐   │
                          │  │  gNB-DU (部分功能) │   │
                          │  │  - MAC / RLC      │   │
       Service Link       │  │  - 部分 High-PHY   │   │      ISL (星间链路)
  ────────────────────────│──│  - 调度/优先级      │───│───────────────────
         (Uu)             │  └──────────────────┘   │     (激光/毫米波)
                          │  ┌──────────────────┐   │
                          │  │  星载路由器       │───│──→ 相邻卫星
                          │  └──────────────────┘   │
                          └──────────────────────────┘
                                │
                     ┌──────────┴──────────┐
                     │   gNB-CU (地面)      │  (或通过 ISL 路由到地面)
                     └──────────┬──────────┘
                                │
                     ┌──────────┴──────────┐
                     │        5GC          │
                     └─────────────────────┘
```

| 优势 | 劣势 |
|:----|:----|
| 减少馈线链路延迟 (无需双跳) | 卫星载荷复杂度显著增加 |
| 星间链路 (ISL) 实现全球覆盖 (无需每星每关口站) | 星上功耗/散热/抗辐射设计挑战 |
| gNB-DU 在星上可做本地调度 | 星上升级困难, 需在轨可重配置 |
| 更适合 LEO 大星座 | 标准化仍在进行 (R18) |

### 8.4 IoT-NTN (R16/R17)

IoT-NTN 是 3GPP 从 R16 开始为 NB-IoT 和 eMTC 通过卫星接入而专门定义的标准轨道。

| 特性 | NR NTN (R17) | IoT NTN (R16/R17) |
|:----|:----|:----|
| 目标技术 | NR (5G 新空口) | NB-IoT / eMTC (LTE 演进) |
| 目标场景 | eMBB / 宽带数据 | mMTC / 窄带物联网 |
| 带宽 | 5–100 MHz (FR1) | 180 kHz (NB-IoT) / 1.4 MHz (eMTC) |
| 峰值速率 | Mbps–Gbps | kbps–100s kbps |
| HARQ 处理 | 禁用或扩展 | 基本禁用 (依赖 RLC ARQ) |
| 覆盖增强 | 标准 NR 覆盖方案 | 额外增强 (重复传输 2048×) |
| UE 类型 | NTN 终端 (手持/VSAT) | 极低成本 IoT 终端 |
| 星座支持 | GEO/GSO/LEO | GEO/GSO 为主 (LEO 研究) |
| 星历精度需求 | 中–高 (米级) | 低–中 (百米级可接受) |
| 3GPP 规范 | R17 TS 38.300 §14 | R16 TR 36.763 (LTE), R17 TS 36.300 §A |
| 典型用例 | 偏远宽带接入、海事/航空 | 资产追踪、环境监测、农业传感 |

**IoT-NTN 关键技术适配**:

| 适配项 | 说明 |
|:----|:----|
| GNSS 非强制 | IoT 终端可不需要 GNSS, 降低成本和功耗 (gNB 提供辅助信息) |
| 半双工 FDD | 仅 NB-IoT 支持半双工, 避免同时收发的硬件复杂度 |
| EDT (Early Data Transmission) | 小数据在随机接入过程中直接传输, 减少信令 |
| 扩展的不连续接收 (eDRX) | 省电模式扩展, IoT 终端可达小时级休眠 |
| 定时松弛 | 比 NR NTN 更宽容的同步精度要求 |
