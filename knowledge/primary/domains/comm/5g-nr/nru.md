# 5G NR-U — 非授权频谱接入

> 最后更新: 2026-06-04
> 关联: [[overview]], [[nr-frame-structure]], [[../lte/overview]]

---

## 1. NR-U 概述

### 1.1 动机与背景

NR-U (NR in Unlicensed Spectrum) 是 3GPP 将 5G NR 扩展到非授权频谱的标准化方案。核心动机：

| 动机 | 说明 |
|:----|:-----|
| **频谱扩展** | 授权频谱稀缺且昂贵，非授权频谱提供大量免费带宽 |
| **容量增强** | 通过载波聚合 (CA) 或双连接 (DC) 聚合授权+非授权频谱 |
| **新部署场景** | 企业专网、工厂自动化、独立非授权频谱运营 |
| **频谱共享** | 与 WiFi、LTE-LAA 等异构系统公平共存 |

### 1.2 目标频段

| 频段范围 | 频率 | 带宽 | 典型应用 |
|:----|:----|:----|:----|
| **5 GHz (UNII-1/2/3)** | 5150–5925 MHz | 每信道 20/40/80 MHz | 全球非授权频谱主力频段 |
| **6 GHz (UNII-5/6/7/8)** | 5925–7125 MHz | 每信道 20/40/80/160 MHz | R16 NR-U 首次引入，R17 增强 |

中国 6GHz 频段 (5925-6425 MHz) 规划中，目前以 5GHz 为主。

### 1.3 3GPP 版本演进

| 版本 | 年份 | 核心内容 |
|:----|:----|:----|
| **R16** | 2020.07 | NR-U 基础框架：LBT、COT、发现突发、独立/辅助接入 |
| **R17** | 2022.06 | 增强 NR-U: 52.6GHz 非授权、URLLC 在非授权频谱、降低 COT 等待时间 |
| **R18** | 2024.03 | NR-U 增强共存、多 TRP 非授权、AI/ML 辅助信道接入 |

核心 3GPP 规范：TS 37.213 (LBT 物理层规程)、TS 38.213 §4 (信道接入)、TS 38.101-1/2 (UE 射频指标)、TS 38.133 (RRM 要求)。

### 1.4 NR-U vs LTE 非授权频谱演进关系

```
LTE-LAA (R13)          NR-U (R16)
    ↓                      ↓
   授权主小区 +            授权主小区 +
   非授权辅小区            非授权辅小区
      ↓                      ↓
eLAA (R14)              NR-U SA (R16)
    ↓                      ↓
   增强上行 LBT            独立非授权运行
      ↓                      ↓
FeLAA (R15)              NR-U 增强 (R17+)
    ↓                      ↓
   6GHz 引入               52.6GHz 支持
```

| 特性 | LTE-LAA (R13) | eLAA (R14) | FeLAA (R15) | NR-U (R16) |
|:----|:---:|:---:|:---:|:---:|
| 下行非授权 | Yes | Yes | Yes | Yes |
| 上行非授权 | No | Yes | Yes | Yes |
| 独立非授权 | No | No | No | Yes |
| 6GHz 支持 | No | No | Yes | Yes |
| 灵活帧结构 | No | No | No | Yes (OFDM 灵活 Numerology) |
| COT 共享 | No | No | No | Yes |
| 宽带 LBT | No | No | No | Yes (20MHz 子带并行) |

### 1.5 全球监管要求对比

| 要求 | ETSI EN 301.893 (欧洲) | FCC Part 15 (美国) | ARIB STD-T71 (日本) |
|:----|:----|:----|:----|
| LBT 强制 | Yes (Cat-4) | No (但推荐) | Yes |
| 信道带宽 | 20 MHz | 20 MHz | 20 MHz (5GHz) |
| OCB 要求 | 占 80% 信道带宽 | 占 80% 信道带宽 | — |
| 发射功率 (5GHz) | 25 mW~1 W (取决于频段) | 1 W (UNII-1/3) | 10 mW/MHz |
| 6GHz AFC | 考虑中 | Yes (AFC 系统) | 考虑中 |

## 2. 信道接入 (LBT)

### 2.1 LBT 分类总览

LBT (Listen Before Talk) 是 NR-U 在非授权频谱运行的核心机制。终端在发送前监听信道，仅在信道空闲时发送。

| 类别 | LBT 类型 | 竞争窗口 | 典型场景 | 对应规范 |
|:----|:----|:----|:----|:----|
| **Cat-1** | 无 LBT (即发) | N/A | COT 共享内的传输 | TS 37.213 §4.1.1 |
| **Cat-2** | 25μs 单次 CCA | N/A | COT 共享、发现突发 | TS 37.213 §4.1.2 |
| **Cat-3** | 随机回退, 固定 CW | 固定 | (NR-U 不使用，保留定义) | TS 37.213 §4.1.3 |
| **Cat-4** | 随机回退, 可变 CW | 可变 (优先级分级) | 初始传输、非 COT 共享 | TS 37.213 §4.1.4 |

### 2.2 Cat-4 LBT 详细流程

```
开始 Cat-4 LBT
    │
    ▼
┌──────────────┐
│ 初始 CCA      │  监听 N_CCA 时隙 (≥ 25μs)
│ (CCA 时隙)    │  空闲 → 进入回退阶段
└──────┬───────┘
       │ 忙 ──────────────────────→ 继续监听直到空闲
       │ 空闲
       ▼
┌──────────────┐
│ 抽取随机数 N  │  N ∈ [0, CW] 均匀分布
└──────┬───────┘
       ▼
┌──────────────┐
│ 空闲感测      │  每个 9μs 时隙: 空闲 → N=N-1
│ (N 递减)      │  忙 → 等待空闲，再继续递减
└──────┬───────┘
       │ N = 0
       ▼
┌──────────────┐
│ 开始传输      │  COT 启动，最大持续时间 = MCOT
└──────────────┘
```

### 2.3 信道接入优先级 (CAPC)

CAPC (Channel Access Priority Class) 决定 Cat-4 LBT 的关键参数。优先级越高 (class 越小)，平均等待时间越短。

| CAPC | p (优先级) | CW_min | CW_max | MCOT (ms) | 适用业务 |
|:----|:---:|:---:|:---:|:---:|:----|
| **Class 1** | 1 | 3 | 7 | 2 | URLLC、高优先级控制信令 |
| **Class 2** | 1 | 7 | 15 | 3 | 实时业务流 (VoNR) |
| **Class 3** | 1 | 15 | 63 | 6/8 | 默认数据业务 (eMBB) |
| **Class 4** | 1 | 15 | 1023 | 6/8 | 尽力而为 (BE) 业务 |

注：MCOT = Maximum Channel Occupancy Time，一次成功 LBT 后允许的最大连续传输时间。

### 2.4 竞争窗口 (CW) 自适应调整

CW 大小根据 HARQ 反馈动态调整：

```
CW 调整算法:
  ┌─────────────────────────────────────────┐
  │  if HARQ-ACK = NACK (且 NACK 比例 ≥ Z%)  │
  │      CW = min(2*CW, CW_max)  // 加倍     │
  │  else (HARQ-ACK = ACK)                   │
  │      CW = CW_min                  // 复位 │
  └─────────────────────────────────────────┘

参考持续时间:
  - DL HARQ 参考窗口: 最近一次 COT 内的 DL 传输
  - UL HARQ 参考窗口: 最近一次 COT 内的 UL 传输
  - Z% 阈值: 默认 80% (TS 37.213 §4.1.4)
```

## 3. NR-U 帧结构

### 3.1 COT (Channel Occupancy Time)

一次成功 LBT 后，设备获得 COT 权利，可在 COT 内连续发送。

```
时间轴:
  空闲 │←── LBT ──│←──────────── COT ────────────→│
       │  竞争窗口  │   (最大 MCOT, 优先级决定)     │ 空闲
       ▼           ▼                                ▼
  ─────┰───────────┰────────────────────────────────┰───────
       │CCA 成功    │ 连续 DL/UL 传输                │ 重新LBT
```

| CAPC | MCOT (ms) | 5GHz | 6GHz | 备注 |
|:----|:---:|:---:|:---:|:----|
| Class 1 | 2 | Yes | Yes | — |
| Class 2 | 3 | Yes | Yes | — |
| Class 3 | 6 | Yes (欧洲) | 8 (FCC) | ETSI: 最大 6ms; FCC: 无 LBT 限制, MCOT 可达 8ms |
| Class 4 | 6/8 | Yes | Yes | 同上 |

### 3.2 COT 共享机制

NR-U 的核心创新之一：**COT 由发起者共享给对方**，对方在 COT 内可免 LBT (或仅 Cat-2) 发送。

```
gNB 发起 COT:
  ┌───────────────────────────────────────────────┐
  │ gNB Cat-4 LBT → DL 突发 → 16μs 间隔 → UE UL   │
  │                 (COT 共享)      (Cat-2 LBT)    │
  └───────────────────────────────────────────────┘

UE 发起 COT (配置授权):
  ┌───────────────────────────────────────────────┐
  │ UE Cat-4 LBT → UL 突发 → 16μs 间隔 → gNB DL   │
  │                 (COT 共享)      (Cat-2 LBT)    │
  └───────────────────────────────────────────────┘
```

**COT 共享条件：**

| 发起者 | 接收者 | LBT 要求 | 最大间隔 |
|:----|:----|:----|:---:|
| gNB (Cat-4) | UE | ≤ 16μs → 免 LBT; 16~25μs → Cat-2 (25μs) | 25μs |
| UE (Cat-4) | gNB | 同 gNB 规则 | 25μs |
| gNB | gNB 自身 (DL→DL) | 16μs 内 → 免 LBT | 16μs |

### 3.3 子帧/时隙边界对齐

NR-U 帧结构关键问题：**NR 的符号/时隙边界与 WiFi 的接入时机如何协调。**

```
NR 符号边界:   |←  OFDM 符号  →|←  OFDM 符号  →|
WiFi 传输:      |←  WiFi PPDU (异步)         →|

NR-U 策略:
  - 非时隙调度: 允许在符号边界开始传输 (非必须时隙边界)
  - 微时隙 (Mini-Slot): 2/4/7 符号调度
  - 起始位置: 符号 0 或符号 7 (中段), 减少对齐开销
```

### 3.4 发现突发 (Discovery Burst)

NR-U 发现突发用于初始接入、RRM 测量和小区发现。窗口内可灵活放置。

| 参数 | 配置 | 说明 |
|:----|:----|:----|
| 周期 | 5/10/20 ms | 一个发现突发窗口周期 |
| 窗口长度 | 5 ms (FR1) | 可在此窗口内任意时刻 Cat-2 LBT 后发送 |
| 内容 | SSB + SIB1 (RMSI) + CSI-RS | 至少占 OFDM 符号 OFDM |
| LBT | Cat-2 (25μs) | 窗口内任何位置 Cat-2 接入 |

```
发现突发窗口 (5ms):
  │←────────────── 5ms 窗口 ──────────────→│
  │   Cat-2 LBT 成功点可变                  │
  │        ↓                                │
  │  ┌─────┬─────┬─────┐                    │
  │  │ SSB │SIB1 │CSI-RS│                  │
  │  └─────┴─────┴─────┘                    │
  └─────────────────────────────────────────┘
```

## 4. 信道占用带宽 (OCB)

### 4.1 OCB 法规要求

根据 ETSI EN 301.893 要求：**发射信号必须占信道带宽的 80% 以上**。

```
信道带宽 = 20 MHz (100 RB, 30 kHz SCS)
占用带宽 ≥ 16 MHz (≥ 80 RB)
实际 NR-U 占用: 接近 20 MHz 全带宽
```

| 法规 | 要求 | NR-U 满足方式 |
|:----|:----|:----|
| ETSI EN 301.893 | OCB ≥ 80% 信道带宽 | 交错 RB 映射 + 全带宽分配 |
| FCC Part 15 | OCB ≥ 80% 信道带宽 | 同上 |
| 发射功率谱密度限制 | ≤ 10 dBm/MHz (ETSI) | 控制每个 RB 的功率 |

### 4.2 资源块交错 (RB Interlacing)

NR-U 引入交错结构以满足 OCB 要求。给定 RB 数量被划分为多个梳状交错。

```
交错定义 (10-交错, 20 MHz/30 kHz SCS, 51 RB):

     交错 #0:  0  10  20  30  40  50  → 6 RB
     交错 #1:  1  11  21  31  41      → 5 RB
     交错 #2:  2  12  22  32  42      → 5 RB
     交错 #3:  3  13  23  33  43      → 5 RB
     交错 #4:  4  14  24  34  44      → 5 RB
     交错 #5:  5  15  25  35  45      → 5 RB
     交错 #6:  6  16  26  36  46      → 5 RB
     交错 #7:  7  17  27  37  47      → 5 RB
     交错 #8:  8  18  28  38  48      → 5 RB
     交错 #9:  9  19  29  39  49      → 5 RB
```

| 信道带宽 | SCS | 交错数 | 每交错 RB 数 | 说明 |
|:----|:---:|:---:|:---:|:----|
| 20 MHz | 15 kHz | 10 | ~10 RB/交错 | 共 106 RB |
| 20 MHz | 30 kHz | 10 | ~5 RB/交错 | 共 51 RB |
| 40 MHz | 30 kHz | 10 | ~10 RB/交错 | 共 106 RB |
| 80 MHz | 30 kHz | 10 | ~21 RB/交错 | 共 217 RB |

注：实际交错分配可能因 CRB 范围、SSB 打孔和 PBCH 预留而略有变化。

### 4.3 PDSCH/PUSCH 交错映射

```
PDSCH 交错映射流程:

阶段 1:  将分配给该 UE 的 VRB 映射到交错索引
阶段 2:  每个交错索引映射到对应的物理 RB (梳状分布)
         (等效于非交错映射 + 频率打散)
阶段 3:  加入 DMRS (按配置密度, 通常每个交错至少 1 个 DMRS)

结果: UE 数据均匀散布在整个信道带宽上 (满足 OCB)
```

PUSCH 交错映射与之对称。DCI Format 0_1/1_1 中的频域资源分配字段指向交错索引而非连续 RB。

## 5. NR-U 物理信道差异

### 5.1 PDCCH

NR-U PDCCH 的主要差异：

| 特性 | NR 授权频谱 | NR-U 非授权频谱 |
|:----|:----|:----|
| CORESET | 频域连续 | 频域交错或分散 (避免 WiFi 突发干扰) |
| 交织 | 可选 (仅 REG bundle 内) | 强制交错 (REG bundle 大小 6) |
| 起始符号 | 固定 (符号 0~3) | 可变 (取决于 LBT 成功时机) |
| 发送时机 | 每个时隙 | 取决于 LBT + COT 窗口 |
| 聚合级别 | 1/2/4/8/16 | 1/2/4/8/16 (建议高级别保证可靠性) |

```
NR-U PDCCH REG Bundle 交错:

CORESET 频域 (12 PRB):
  ┌──────────────┐
  │  连续 REG    │  授权频谱: 直接映射
  │  1-2-3-4-5-6 │
  └──────────────┘
  ┌──────────────┐
  │  交错 REG    │  NR-U:  跨带宽分布
  │  1  3  5  2  │  减少 WiFi 碰撞概率
  │    4  6      │
  └──────────────┘
```

### 5.2 PUCCH

NR-U 优选短格式 PUCCH，以降低 LBT 开销：

| PUCCH 格式 | 长度 | NR-U 适应性 | 说明 |
|:----|:---:|:---:|:----|
| **Format 0** | 1-2 符号 | 优 | 短格式，Cat-2 LBT 即可在 COT 内发送 |
| **Format 1** | 4-14 符号 | 可用 (COT 内) | 需要连续占用 |
| **Format 2** | 1-2 符号 | 优 | 短格式 UCI (CSI 反馈) |
| Format 3 | 4-14 符号 | 受限制 | 需 Cat-4 LBT (长格式) |
| Format 4 | 4-14 符号 | 受限制 | 同上 |

### 5.3 SRS (探测参考信号)

| 特性 | NR | NR-U |
|:----|:----|:----|
| 发送时机 | 周期性可配 | 受 LBT 约束 — 以**突发 SRS** 为主 |
| SRS 资源集用法 | CB/BM/ANT 切换 | 增加 'NR-U' 用途分类 |
| 起始位置 | 固定符号 | 可优化到 COT 开始符号附近 |

### 5.4 PUSCH

| 特性 | NR | NR-U |
|:----|:----|:----|
| 频域分配 | 连续 VRB | **交错 VRB** (梳状) |
| 正交序列 | 不强制 | **强制正交序列** (改善多 UE 共存) |
| 起始符号 | 灵活 | 受 LBT 成功时间约束 (微时隙) |
| CG 配置授权 | 周期性 | **CG 周期 + COT 共享**，UE 可在 gNB COT 内免 LBT |

### 5.5 HARQ 机制

| 特性 | NR | NR-U |
|:----|:----|:----|
| HARQ 反馈 | 同步 + 异步可选 (DL), 同步 (UL) | **异步自适应** (DL + UL) |
| 重传时机 | 固定时序，固定资源 | 灵活资源 (每次重新调度) |
| 反馈码本 | Type-1 semi-static / Type-2 dynamic | 增强 Type-2 + **增强 Type-3** (NR-U 特殊) |
| 反馈时间 | 按 HARQ 时序 (k1) | 可扩展到 COT 边界之外 (`DL-datatToUL-ACK` 扩展) |

## 6. 初始接入与同步

### 6.1 NR-U SSB 配置

NR-U SSB 周期性较 NR 更灵活，理由是 LBT 不确定性。

| 参数 | NR (授权) | NR-U (非授权) |
|:----|:----|:----|
| SSB 周期 | 5/10/20/40/80/160 ms | 5/10/20 ms (推荐 20 ms) |
| 发现突发窗口 | N/A | 5 ms 窗口 (首次发送可滑动) |
| SSB 波束数 (FR1) | 1-8 | 1-8 (通常 4) |
| LBT 类型 | N/A | Cat-2 (25μs) 在发现窗口内 |

### 6.2 SSB 时频位置

```
NR-U SSB 候选位置 (20 MHz, SCS=30 kHz, 发现突发窗口=5ms):

  ┌──────────────────────────────────────┐
  │ 时隙 0     时隙 1     ...             │
  │ ┌──┬──┐  ┌──┬──┐                     │
  │ │SSB│  │  │SSB│  │  最多 10 个候选    │
  │ │#0 │  │  │#1 │  │  (5ms 内)          │
  │ └──┴──┘  └──┴──┘                     │
  └──────────────────────────────────────┘

实际发送位置: 取决于 LBT 成功时机 + 候选位置
  - 不能保证在第一个候选位置成功 LBT
  - 一旦成功，发送一次或多次 SSB (视波束数)
```

### 6.3 NR-U PRACH

| 特性 | NR | NR-U |
|:----|:----|:----|
| PRACH 前导格式 | A1-A3, B1-B4, C0-C2 | A1-A3, B1-B4 (增加 NR-U 特定格式) |
| PRACH 时机 | 基于时隙配置 | 基于配置 + LBT (Cat-4 或 Cat-2 在 COT 内) |
| PRACH 掩码 | N/A | **PRACH Mask Index** 控制 UE 在特定子帧前导 |
| LBT 失败处理 | N/A | 功率提升 + 每次尝试独立 LBT |

### 6.4 RAR 窗口扩展

```
RAR 窗口 (NR):  [msg1 发送]  固定窗口 (2-10ms)   [msg2 接收]
RAR 窗口 (NR-U): [msg1]  扩展窗口 (最大 40ms)  [msg2]

原因: gNB 可能因 LBT 失败无法在固定窗口内回复 RAR
   → NR-U 允许 ra-ResponseWindow 扩展到 40ms
   → 支持增强 Type-3 HARQ 码本，可在 COT 外部反馈 RAR ACK
```

## 7. 与其他技术共存

### 7.1 NR-U 与 WiFi (802.11ax/be) 共存

NR-U 和 WiFi 在相同非授权信道工作，通过**共同 LBT 机制**协调信道接入。

| 特性 | WiFi 6 (802.11ax) | WiFi 7 (802.11be) | NR-U (R16) |
|:----|:----|:----|:----|
| 信道接入 | CSMA/CA (EDCA) | CSMA/CA + MLO | Cat-4 LBT (等同于 EDCA) |
| CCA 时隙 | 9 μs | 9 μs | 9 μs |
| 回退机制 | 指数回退 (CW_min→CW_max) | 同左 | 指数回退 (等同) |
| 最大 TXOP/COT | 5.484 ms | 5.484 ms | 最大 8 ms (FCC) |
| 最小感测 | -82 dBm (CCA) | -82 dBm | -72 dBm (能量检测) |
| 竞争窗口 | 15-1023 (BE) | 15-1023 (BE) | 15-1023 (CAPC 3/4) |

**关键公平性指标：**

```
NR-U vs WiFi 公平性:
  - NR-U CAPC 3 的 CW_min=15 几乎等于 WiFi AC_BE 的 CW_min=15
  - NR-U 的 9μs CCA 时隙与 WiFi 完全对齐
  - NR-U MCOT 可达 8ms (vs WiFi TXOP 5.484ms)
    → 可能需要权衡 (R17 引入了限制 COT 长度的增强公平性机制)
```

### 7.2 NR-U 与 LTE-LAA 共存

| 共存维度 | NR-U 优势 |
|:----|:----|
| LBT 参数 | 与 LTE-LAA 兼容 (9μs 时隙, ED 阈值) |
| 帧结构 | NR-U 更灵活 (微时隙、非时隙调度)，减少碰撞概率 |
| COT 共享 | NR-U 的 gNB↔UE COT 共享是 LTE-LAA 不支持的 |
| 宽带操作 | 两者均通过 20MHz 子带并行 LBT 接入大带宽 |

### 7.3 6GHz AFC (Automatic Frequency Coordination)

FCC 对 6GHz 非授权频谱强制 AFC 系统协调。

```
AFC 架构:
  ┌──────────┐   查询请求 (位置/天线高度/带宽)   ┌───────────┐
  │  AFC     │ ←──────────────────────────────→ │  AFC       │
  │  客户端   │                                  │  服务端    │
  │  (gNB)    │   授权响应 (功率限制/频段)        │  (云端)    │
  └──────────┘                                  └───────────┘

AFC 合规要求:
  - gNB 必须先查询 AFC 服务器获取授权 (每天/每周)
  - AFC 返回最大 EIRP、允许频段、功率谱密度限制
  - 保护已有微波链路 (固定业务)
```

### 7.4 NR-U vs WiFi 吞吐量公平性对比

| 场景 | NR-U 吞吐量 (Mbps) | WiFi 6 吞吐量 (Mbps) | 公平性比率 |
|:----|:---:|:---:|:---:|
| 单 NR-U + 单 WiFi, 20MHz | 45-55 | 35-45 | ~1.2:1 |
| 单 NR-U + 2 WiFi, 20MHz | 30-38 | 25-32 (平均) | ~1.1:1 |
| 单 NR-U + 单 WiFi, 80MHz | 240-280 | 180-220 | ~1.3:1 |
| NR-U MCOT=6ms vs WiFi TXOP=3ms | — | — | NR-U 偏向 (R17 改进) |

注：数据来自 3GPP TR 38.889 性能仿真。实际性能受部署和环境显著影响。

## 8. NR-U 部署场景

### 8.1 部署模式总结

| 模式 | 授权锚点 | 非授权载波 | 控制面位置 | 典型用例 |
|:----|:---:|:---:|:----|:----|
| **NR-U 辅助 (LTE-NR DC)** | LTE 锚点 | NR-U 辅载波 | LTE (EN-DC) | 早期部署, 利用已有 LTE 基站 |
| **NR CA + NR-U** | NR 锚点 (FR1) | NR-U 辅载波 | NR (锚点) | 5G SA 部署 |
| **独立 NR-U** | 无 | NR-U | NR-U | 企业专网、工厂、新部署 |
| **双连接 NR-U** | NR (FR1/FR2) | NR-U | 锚点 NR | 容量增强 |

### 8.2 EN-DC 与 NR-CA 对比

```
EN-DC (LTE-NR 双连接):
  ┌──────────┐     ┌──────────────┐
  │ LTE 锚点  │────>│  EPC         │
  │ (授权频谱) │     └──────────────┘
  │ + NR-U    │
  │ (非授权)   │   控制面: LTE; 用户面: LTE + NR-U
  └──────────┘

NR-CA (NR 载波聚合):
  ┌──────────┐     ┌──────────────┐
  │ NR 锚点   │────>│  5GC         │
  │ (授权频谱) │     └──────────────┘
  │ + NR-U    │
  │ (非授权)   │   控制面: NR锚点; 用户面: NR 锚点 + NR-U
  └──────────┘
```

### 8.3 企业/工厂专网场景

| 需求 | NR-U 方案 | 优势 |
|:----|:----|:----|
| 独立部署 | NR-U SA | 无需运营商授权频谱 |
| 低延迟 | CAPC 1 (CW=3-7) + 微时隙 | 快速信道接入 |
| 高可靠 | 重复传输 + 低码率 | 减少 LBT 失败影响 |
| 时间敏感网络 (TSN) | NR-U + COT 预留 | R17 增强了 URLLC 在非授权频谱的 TSN 支持 |
| 室内定位 | NR-U 定位 (R18) | 利用 5GHz/6GHz 大带宽 |

### 8.4 R17 增强：NR-U 到 52.6GHz

R17 将 NR-U 扩展到毫米波非授权频谱 (52.6–71 GHz)。

| 特性 | FR1 NR-U (5/6GHz) | FR2 NR-U (52.6GHz+) |
|:----|:----|:----|
| 数理 (Numerology) | 15/30/60 kHz SCS | 60/120/480/960 kHz SCS |
| 信道带宽 | 20/40/80 MHz | 50/100/200/400 MHz |
| LBT 机制 | Cat-4 (定向 + 全向) | 定向 LBT (空间复用增强) |
| COT | 最大 8ms | 最大 5ms |
| 波束管理 | 基础 | 增强波束管理 + 波束失败恢复 |
| 用途 | 室内/室外 eMBB | 超高容量回传、固定无线接入 |
