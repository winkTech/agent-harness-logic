# 5G NR LDPC BG1/BG2 -- 与 802.11n QC-LDPC 对比

> 最后更新: 2026-06-04
> 关联: [[overview]], [[../ldpc/algorithm_spec]], [[../ldpc/encoding_spec]]

---

## 1. 概述

### 1.1 NR LDPC 的背景

3GPP 在 5G NR (New Radio) 标准化过程中，对数据信道编码方案进行了全面评估。最终选定：

| 信道类型 | 编码方案 | 理由 |
|:--------|:--------|:-----|
| **数据信道** (PDSCH/PUSCH) | **LDPC** | 高吞吐、并行译码、HARQ-IR 支持 |
| **控制信道** (PDCCH/PUCCH) | **Polar** | 短块性能优异、无错误平层 |
| **广播信道** (PBCH) | **Polar** | 同控制信道，统一设计 |

选择 LDPC 作为数据信道编码的核心原因：

1. **HARQ 增量冗余 (IR)**: LDPC 天然支持速率匹配和增量冗余，不同 RV (Redundancy Version) 发送不同码位，HARQ 合并增益显著。Polar 码的速率匹配基于打孔/缩短，IR 灵活性较差。
2. **高码率性能**: 数据信道码率可达 8/9 (~0.89)，LDPC 在高码率下的性能优于 Turbo/Polar。
3. **大规模并行译码**: LDPC 的 BP (Belief Propagation) 译码可高度并行化，满足 NR 峰值速率要求 (eMBB 下行 20 Gbps)。
4. **产业成熟度**: LDPC 已在 WiFi (802.11n/ac/ax) 和 DVB-S2 等标准中得到验证。

### 1.2 802.11n QC-LDPC 与 NR LDPC 的基本定位差异

| 维度 | 802.11n QC-LDPC | NR LDPC |
|:----|:---------------|:--------|
| 应用场景 | WLAN 室内/短距 | 蜂窝网络 广域/高速 |
| 码块长度 | 固定 (648/1296/1944) | 灵活 (按 TBS 分块) |
| 码率灵活性 | 4 种固定码率 | 几乎连续可调 (通过速率匹配) |
| 提升因子 | 3 种 (27/54/81) | 64 种 Zc (Se 0-7) |
| HARQ | CC (Chase Combining) | IR (Incremental Redundancy) |
| 编码复杂度 | 低 (双对角直接计算) | 中 (需速率匹配 + LBRM) |
| 译码延迟 | 低 (基矩阵小) | 中高 (基矩阵大, 但吞吐更高) |
| 标准化 | IEEE 802.11n §20.3.11.6 | 3GPP TS 38.212 §5.2 |

**核心区别**: 802.11n LDPC 为 WiFi 场景优化 -- 固定码长、简单编码、低延迟；NR LDPC 为蜂窝场景优化 -- 灵活码长/码率、HARQ-IR、高吞吐。

## 2. 802.11n QC-LDPC 回顾

### 2.1 标准与参数

基于 IEEE 802.11n/ac/ax 标准的 QC-LDPC 码：

| 参数 | 值 | 说明 |
|:----:|:---|:----|
| 码块长度 N | 648, 1296, 1944 | 3 种固定码长 |
| 提升因子 Z | 27, 54, 81 | Z = N / 24 |
| 码率 R | 1/2, 2/3, 3/4, 5/6 | 4 种固定码率 |
| 子块列数 nb | 24 | 固定 |
| 子块行数 mb | 12, 8, 6, 4 | 随码率变化 |
| 母矩阵 H | mb x nb 子块矩阵 | 每个子块是 ZxZ 循环置换或零矩阵 |

### 2.2 结构化双对角校验矩阵 (IRA 结构)

802.11n QC-LDPC 使用 IRA (Irregular Repeat-Accumulate) 结构，校验部分为双对角形式：

```
H = [H_s | H_p]

其中 H_p (mb x mb 子块) 具有双对角结构:
     ┌                             ┐
     │ I  I  0  0  ...  0      0  │
     │ 0  I  I  0  ...  0      0  │
     │ 0  0  I  I  ...  0      0  │
     │ ...                        │
     │ I  0  0  0  ...  0      I  │  ← 首行非零项在首列和末列
     └                             ┘
```

> 注: 802.11n R=1/2, N=648 的实际 H_p 存在秩亏 (rank = 322, 非 324)，详见 [[../ldpc/encoding_spec]]。

### 2.3 编码方法

双对角结构的优势在于**编码简单** -- 可通过前向/后向代入直接计算校验位，无需矩阵求逆：

```
编码步骤 (Richardson-Urbanke ALT 分解):
1. 将 H 矩阵分解为 H = [A B T; C D E], 其中 T 为下三角
2. 通过前向代入计算 parity_1
3. 通过后向代入计算 parity_2
```

### 2.4 优点与局限

| 优点 | 局限 |
|:----|:----|
| 编码延迟低 (双对角直接计算) | 码长受限 (仅 3 种) |
| 硬件实现简单 (前向/后向代入) | 码率不灵活 (仅 4 种) |
| 译码并行度适中 (Z=27/54/81) | 不支持 HARQ IR (仅 Chase Combining) |
| 产业验证充分 (WiFi 广泛部署) | 速率匹配仅为简单打孔 |
| 错误平层低 | 不支持灵活 TBS (Transport Block Size) |

## 3. NR LDPC 码设计 -- BG1 vs BG2

NR LDPC 的核心创新是采用**双基图 (Base Graph)** 设计，以覆盖 eMBB 场景下从极小包 (几十 bit) 到极大包 (数千 bit) 的 TBS 范围。

### 3.1 BG1 (Base Graph 1) -- 大块数据

| 参数 | 符号 | 值 | 说明 |
|:----|:----:|:--:|:----|
| 信息列数 | Kb | 22 | 系统列数 |
| 总列数 | nb | 68 | 母矩阵总列数 |
| 校验列数 | mb | 46 | nb - Kb |
| 母矩阵尺寸 | -- | 46 x 68 | H_BG × Zc |
| 原生码率 | R_native | 22/68 ≈ 1/3 | 通过打孔实现更高码率 |
| 最大信息长度 | K_max | 22 x 384 = 8448 bit | Kb x Zc_max |
| 最小信息长度 | K_min | 22 x 2 = 44 bit (理论) | 实际 TBS >= 24 |
| 典型 TBS 范围 | -- | 140 ~ 8448 bit | 中等至大块 |
| 目标码率范围 | -- | 1/3 ~ 8/9 (≈ 0.33 ~ 0.89) | 含极高码率 |

**BG1 母矩阵结构特征**:
- 前 22 列为系统列 (信息位)
- 第 23-68 列为校验列
- **核心校验区** (行 1-4, 列 23-26) 确保最小码率 1/3 的可靠译码
- **扩展校验区** (行 5-46) 提供更低码率的额外校验
- 高码率通过**打孔前 2 系统列**实现: Kb 从 22 减至 20，有效码率 = 20/(20+mb_reduced)

### 3.2 BG2 (Base Graph 2) -- 小块数据

| 参数 | 符号 | 值 | 说明 |
|:----|:----:|:--:|:----|
| 信息列数 | Kb | 10 | 系统列数 |
| 总列数 | nb | 52 | 母矩阵总列数 |
| 校验列数 | mb | 42 | nb - Kb |
| 母矩阵尺寸 | -- | 42 x 52 | H_BG × Zc |
| 原生码率 | R_native | 10/52 ≈ 1/5 | 更低原生码率适配小块 |
| 最大信息长度 | K_max | 10 x 384 = 3840 bit | Kb x Zc_max |
| 最小信息长度 | K_min | 10 x 2 = 20 bit (理论) | 实际 TBS >= 12 |
| 典型 TBS 范围 | -- | 12 ~ 2560 bit | 小块数据 |
| 目标码率范围 | -- | 1/5 ~ 2/3 | 中低码率 |

**BG2 母矩阵结构特征**:
- 前 10 列为系统列 (更少的系统列以适配小块)
- 第 11-52 列为校验列
- 原生码率更低 (1/5)，为小块在差信道条件下提供更强劲的纠错能力
- **行密度更低** (行重更小)，降低小块的译码复杂度

### 3.3 BG1 vs BG2 选择准则

选择逻辑定义于 TS 38.212 §7.2.2:

```
IF TBS <= 292:
    使用 BG2
ELSE IF TBS <= 3824 AND R <= 2/3:
    使用 BG2
ELSE:
    使用 BG1
```

| TBS 范围 | 码率范围 | 选择 | 典型场景 |
|:---------|:--------|:----:|:--------|
| <= 292 | 任意 | **BG2** | URLLC 小包 / 短消息 |
| 293-3824 | R <= 2/3 | **BG2** | 语音 (VoNR) / CQI 反馈 |
| 293-3824 | R > 2/3 | **BG1** | 小 TBS 高码率 (罕见) |
| > 3824 | 任意 | **BG1** | eMBB 视频 / FTP / 网页 |

> 直观理解: **BG1 管"大块 + 中高码率"，BG2 管"小块 + 中低码率"。**

### 3.4 BG1 vs BG2 母矩阵结构对比

| 维度 | BG1 | BG2 |
|:----|:---:|:---:|
| 母矩阵尺寸 | 46 x 68 | 42 x 52 |
| 信息列 Kb | 22 | 10 |
| 校验列 mb | 46 | 42 |
| 系统列重 (平均) | 3-5 | 3-4 |
| 校验列重 (平均) | 3-7 | 3-6 |
| 双对角行范围 | 交错分布 | 交错分布 |
| 原生码率 | ~1/3 | ~1/5 |
| 核心校验行 | 1-4 | 1-4 |
| 扩展校验行 | 5-46 | 5-42 |
| 最大打孔列 | 2 (列 1-2) | 2 (列 1-2) |

## 4. NR LDPC 提升与 CRC 设计

### 4.1 提升因子 Zc

NR LDPC 定义了 8 个提升因子集合 (Set 0-7)，每个集合 8 个 Zc 值，共 64 个。每个集合对应一个 a 值 (用于移位系数计算)。

| Set 索引 (i_LS) | a | Zc 值 |
|:---------------:|:-:|:------|
| 0 | 2 | 2, 4, 8, 16, 32, 64, 128, 256 |
| 1 | 3 | 3, 6, 12, 24, 48, 96, 192, 384 |
| 2 | 5 | 5, 10, 20, 40, 80, 160, 320 |
| 3 | 7 | 7, 14, 28, 56, 112, 224 |
| 4 | 9 | 9, 18, 36, 72, 144, 288 |
| 5 | 11 | 11, 22, 44, 88, 176, 352 |
| 6 | 13 | 13, 26, 52, 104, 208 |
| 7 | 15 | 15, 30, 60, 120, 240 |

**Zc 选择规则**: 对给定 Kb 和 TBS，取满足 Kb * Zc >= K 的最小 Zc。

### 4.2 提升机制

NR LDPC 的提升基于循环置换矩阵 (CPM)，定义于 TS 38.212 §5.2.2:

```
母矩阵中的每个非零项 P_{i,j} → 循环移位值为:
  shift = mod(P_{i,j}, Zc)    (如果 P_{i,j} >= 0)
  shift = -1                  (如果 P_{i,j} < 0, 表示零矩阵)
```

与 802.11n 的关键区别: NR LDPC 母矩阵中的移位值 P_{i,j} 是**针对最大 Zc (=384) 设计的**，实际使用时通过 `mod(P_{i,j}, Zc)` 取模运算得到当前 Zc 对应的移位值。这种设计确保了从 Zc=2 到 Zc=384 的全程兼容。

### 4.3 校验位双打孔 (Always Punctured)

NR LDPC 总是打孔前 2 个系统列 (索引 1-2，1-indexed) 对应的 Zc*2 个校验位 (由系统列经核心校验行产生的 parity)，原因是:

1. **提升母矩阵的"有效"码率**: 打孔后有效 Kb' = Kb - 2，码率得以提升
2. **加强结构**: 被打孔的列在接收端作为"已知为零"的位，增强了核心校验方程
3. **适配高码率**: 打孔后 BG1 最高码率可达 8/9

### 4.4 CRC 附加

| 参数 | BG1 | BG2 |
|:----|:---:|:---:|
| CRC 多项式 | 24A (g_CRC24A) | 24B (g_CRC24B) |
| CRC 长度 | 24 bit | 24 bit |
| 适用条件 | TBS > 3824 | TBS <= 3824 |
| 码块级 CRC | 24B (如果分段) | 24B (如果分段) |

## 5. 802.11n vs NR LDPC 详细对比

### 5.1 核心参数对比

| 维度 | 802.11n QC-LDPC | NR BG1 | NR BG2 |
|:----|:-------|:-------|:------|
| 母矩阵大小 | 12 x 24 (R=1/2) | 46 x 68 | 42 x 52 |
| 信息块大小 (bit) | 324 ~ 1944 | 140 ~ 8448 | 12 ~ 2560 |
| 提升因子 | 3 种 (27/54/81) | 64 种 Zc (2~384) |
| 码率范围 | 1/2 ~ 5/6 | 1/3 ~ 8/9 | 1/5 ~ 2/3 |
| 双对角行 | 连续 (row 1-11) | 交错分布 |
| 校验块结构 | IRA (完整双对角) | 类双对角 (核心 + 扩展) |
| 编码方法 | ALT 前向/后向代入 | ALT 分解 + 速率匹配 |
| HARQ 支持 | CC (Chase Combining) | IR (增量冗余) |
| 速率匹配 | 简单打孔/重复 | 循环缓存 (LBRM) |
| 打孔列 | 无 (系统形式) | 固定 2 列打孔 |
| CRC | 无 LDPC 层 CRC | 24A (BG1) / 24B (BG2) |

### 5.2 编码器结构对比

| 维度 | 802.11n | NR LDPC |
|:----|:-------|:--------|
| 系统编码 | 是 (info_bits 在码字前部) | 是 (经速率匹配后仍保持系统形式) |
| 编码步骤 | 1 步 (ALT 前向/后向代入) | 多步: 打孔 → 编码 → 速率匹配 |
| 矩阵运算 | ZxZ 子块级运算 | ZcxZc 子块级运算 |
| 并行度 | Z (=27/54/81) | Zc (= 2~384) |
| 编码延迟 | O(N) | O(N) + 速率匹配开销 |
| 硬件友好性 | 高 (双对角直接计算) | 中 (需支持多 Zc 和多 RV) |

### 5.3 译码器结构对比

| 维度 | 802.11n | NR LDPC |
|:----|:-------|:--------|
| 基矩阵大小 | 12 x 24 ~ 4 x 24 | 46 x 68 (BG1) / 42 x 52 (BG2) |
| VN 数 | 24 个子块 | 68/52 个子块 |
| CN 数 | 12~4 个子块 | 46/42 个子块 |
| 译码并行度 | Z (27/54/81) | Zc (2~384) |
| 典型迭代 | 10~20 | 20~50 |
| 收敛速度 | 快 (小基矩阵) | 较慢 (大基矩阵) |
| 早停策略 | 校验方程全部满足 | 校验方程全部满足 + CRC 校验 |
| 译码吞吐 | 中 (< 1 Gbps) | 高 (可达 20 Gbps @ eMBB) |

## 6. NR LDPC 编码流程

### 6.1 完整编码链路 (TS 38.212 §5.2, §7.2)

```
TBS (Transport Block Size)
   │
   ▼
TBS + CRC (24A / 24B)
   │
   ▼
码块分段 ──→ 每段 + 码块 CRC (24B, 如果分段)
   │
   ▼
选择 BG1 或 BG2 (基于 TBS + 码率)
   │
   ▼
确定 Zc (提升因子)
   │
   ▼
LDPC 编码 (基于母矩阵 + Zc)
   │
   ▼
速率匹配 (循环缓存, RV 选择)
   │
   ▼
码块级联
   │
   ▼
输出: N_bits = G (调度的物理资源数)
```

### 6.2 速率匹配 -- 循环缓存 (Circular Buffer)

NR LDPC 的速率匹配基于**循环缓存**结构，支持 HARQ IR:

```
码字 = [S0, S1, ..., S_{Kb-1}, P0, P1, ..., P_{mb-1}]
         \_____  ____________/  \_____  ____________/
              信息位 (系统位)         校验位

循环缓存排列 (系统位优先):
  [S0, S1, ..., S_{Kb-1}, P0, P1, ..., P_{mb-1}]
   \_______________________/  \___________________/
         K = Kb * Zc              M = mb * Zc

打孔: 移除前 2*Zc 位 (前 2 个系统列)
     有效缓存大小: N_cb = (Kb + mb) * Zc - 2*Zc
```

**冗余版本 (RV) 选择**:

| RV | 起始位置 k0 | 说明 |
|:-:|:-----------|:----|
| 0 | 2 * Zc | 从第 3 个系统列开始 (默认) |
| 1 | floor(17*N_cb/66) | 约 26% 处 |
| 2 | floor(33*N_cb/66) | 约 50% 处 |
| 3 | floor(56*N_cb/66) | 约 85% 处 |

**HARQ IR 原理**: 初次发送 RV0，重传时选择不同 RV 发送不同码位。接收端将对数似然比 (LLR) 合并到循环缓存对应位置，实现增量冗余增益。

### 6.3 LBRM (Limited Buffer Rate Matching)

NR 引入 LBRM 限制循环缓存大小以控制 UE 的译码器缓存：

```
N_cb = min(N, N_ref)

其中 N_ref = floor(25344 / R_LBRM)
R_LBRM = 2/3 (固定)
```

该机制保证 UE 译码器缓存上限为 25344 bit (约 3168 byte)。

## 7. NR LDPC 译码概述

### 7.1 分层 BP / Min-Sum 算法

NR LDPC 译码采用分层调度 (Layered Scheduling) 的 BP 或 Min-Sum 算法：

**分层 BP 流程**:
```
1. 初始化: LLR 从解调器输入填充循环缓存
2. 逐行更新 (按基矩阵的 mb 行):
   for layer = 1:mb:
       读入该层所有 VN 的 LLR
       计算 CN→VN 消息 (BP: tanh 规则; Min-Sum: min 近似)
       更新 VN LLR
       回写更新后的 VN LLR
3. 早停判断:
       - 校验方程全部满足 → 提前终止
       - CRC 校验通过 → 提前终止
4. 达到最大迭代次数 → 输出硬判决
```

**Min-Sum 近似** (降低硬件复杂度):
```
CN→VN 消息 = α * Π(sign) * min(|LLR|)

其中 α 为归一化因子 (典型 0.75~0.875)
```

### 7.2 与 802.11n 译码对比

| 维度 | 802.11n | NR BG1 | NR BG2 |
|:----|:-------|:-------|:------|
| 基矩阵行数 | 4~12 | 46 | 42 |
| 每层 VN 数 | 3~6 | 3~7 | 3~6 |
| 层更新复杂度 | 低 | 中高 | 中 |
| 收敛速度 | **快** (小基矩) | **较慢** (大基矩) | **中等** |
| 典型迭代 | 10~20 | 25~50 | 20~40 |
| 译码吞吐 (单核) | < 1 Gbps | 1~5 Gbps | 0.5~2 Gbps |
| 码率灵活性 | **低** (固定 4 种) | **高** (几乎连续) |
| 早停 | 校验方程 | 校验方程 + CRC |
| 硬件规模 | **小** (~10万门) | **大** (~50~100万门) |

### 7.3 NR LDPC 译码器的挑战

1. **大基矩阵的收敛性问题**: BG1 有 46 层，分层调度中信息传播需要多轮迭代。解决方案：
   - 自适应的最大迭代次数 (根据 SNR 动态调整)
   - 多层并行更新 (同时更新多个非重叠行)
2. **多 Zc 支持**: 译码器需要支持 64 种 Zc 值。解决方案：
   - 按最大 Zc=384 设计硬件，小 Zc 时折叠重用
   - 控制逻辑按 Set 分组简化
3. **高吞吐要求**: eMBB 要求下行 20 Gbps。解决方案：
   - 多个译码核心并行 (Carrier Aggregation)
   - 流水线化分层调度
   - Min-Sum 近似 + 归一化常数优化
