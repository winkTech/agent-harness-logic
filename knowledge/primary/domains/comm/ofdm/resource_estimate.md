# OFDM 发射机 资源评估报告

> 基于阶段3定点结果: 16bit, IFFT输入 Q2.14, IFFT输出 Q3.13

## 1. DSP48 映射分析

### 1.1 定点位宽与 DSP48 适配

DSP48E1 乘加器规格: 25bit × 18bit + 48bit

| 运算 | 位宽 | DSP48 利用率 | 每运算消耗 |
|------|------|-------------|-----------|
| IFFT 复乘 | 16×16 | 16×16 → 1个DSP48 (在25×18范围内) | 3 DSP48 |
| IFFT 蝶形加 | 16+16 | LUT实现 | 0 DSP48 |
| IFFT 旋转因子 | 16bit 存ROM | 不消耗DSP | 0 DSP48 |

关键结论: **16bit 位宽完美适配 1个DSP48 完成一次乘法**，无需位宽拆分。
若位宽 > 18bit → 需 2个DSP48 级联，资源翻倍。

### 1.2 IFFT Core (Xilinx FFT IP, N=64, 16bit)

| 配置项 | 设定 |
|--------|------|
| Architecture | Pipelined Streaming |
| Data Width | 16bit |
| Phase Factor Width | 16bit |
| Scaling | Block Floating Point |
| Memory Type | BRAM |
| DSP48 Usage | 12 |

### 1.3 各模块 DSP48 明细

| 模块 | 运算 | 位宽 | 并行度 | DSP48 |
|------|------|------|--------|-------|
| Mod Mapper | 无乘法 | LUT映射 | - | 0 |
| Pilot Insert | 无乘法 | 控制逻辑 | - | 0 |
| **IFFT Core** | **复乘×6级** | **16bit** | **流式** | **12** |
| CP Insert | 无乘法 | RAM读写 | - | 0 |
| DC/Guard插入 | 无乘法 | 控制逻辑 | - | 0 |
| **总计** | | | | **12** |

## 2. 架构缩放方案

基于 16bit 定点数据，三种架构对比:

| 方案 | 架构 | DSP48 | LUT | BRAM | 吞吐 | 延迟 |
|------|------|-------|-----|------|------|------|
| **A: 全并行(推荐)** | FFT IP流式 | **12** | 2800 | 3 | **1/sample** | 65clk |
| B: 半并行 | 2路时分FFT | 8 | 2200 | 4 | 2/sample | 80clk |
| C: 最小面积 | 基-2串行 | 4 | 1500 | 2 | ~64/symbol | 200clk |

**推荐: 方案A** — 连续吞吐=1 sample/clk 是通信基带处理的基本要求

## 4. 替代映射分析

### 4.1 LUT 替换 DSP48 的边界

OFDM 发射机中 IFFT 是唯一使用 DSP48 的模块。
Xilinx FFT IP Core 的 DSP48 使用量已是最优，不建议手动替换。

| 替换方案 | 节省DSP48 | 额外LUT | 时序影响 | 建议 |
|----------|----------|---------|----------|------|
| LUT代替IFFT DSP | 12 | ~3000 | 频率下降~20% | ❌ 不推荐 |
| BRAM代替旋转因子ROM | 0 | 0 | 无 | 已使用BRAM |
| 分布式LUT代替BRAM | 0 | ~400 | 无 | 没必要 |

### 4.2 优化建议

| 场景 | 建议 | 效果 |
|------|------|------|
| 资源极度紧张 | 选择方案C(串行FFT) | DSP48从12→4，但吞吐降为1/64 |
| 需要成形滤波 | 用 Xilinx FIR Compiler | 使用DSP48但效率高 |
| 多通道(2×2 MIMO) | 用2个FFT IP | 线性扩展，DSP48=24 |
